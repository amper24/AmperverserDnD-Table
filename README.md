# Edge Tablet (Amperverser DnD Table)

Виртуальный стол для D&D 5e в духе Owlbear Rodeo: кампании, приглашения по ссылке, роли **мастер/игрок**, сцены с картами и токенами, туман войны, линейка, рисование, чат с кубиками, инициатива, листы персонажей и справочник на русском (расы, классы, предыстории, предметы, заклинания, бестиарий, черты, состояния).

**Стек:** Rust (axum · tokio · sqlx) · **MySQL** или SQLite · WebSocket · фронтенд на чистом JS/Canvas, встроен в бинарник. Один исполняемый файл, без внешних зависимостей.

## Быстрый старт

### Одной командой
```bash
curl -fsSL https://raw.githubusercontent.com/amper24/AmperverserDnD-Table/main/install.sh | bash
```
Сам выбирает способ: Docker (с MySQL) → cargo → готовый бинарник из Releases. Переменные: `DND_DIR`, `DND_MODE=docker|cargo|binary`, `PORT`.

### Docker Compose (MySQL + приложение)
```bash
cp .env.example .env
docker compose up -d --build
```
`config.yml` создаётся в томе `dnd_data` (`/app/data/config.yml` внутри контейнера); переменные из `.env` перекрывают его.

### Pterodactyl (generic Rust egg)
Импортируйте `deploy/pterodactyl-egg.json` (Admin → Nests → Import Egg) — это стандартный [generic-rust](https://eggs.pterodactyl.io/egg/generic-rust-generic/) egg с преднастроенным репозиторием и переменными (`DATABASE_URL`, SMTP). Старт: `cargo run --release`; порт берётся из `SERVER_PORT` автоматически; строка готовности — `Server listening on`. Настройки — в `config.yml` в корне сервера (File Manager); он создаётся при первом старте. Заполненные переменные панели перекрывают файл; чтобы панель не мешала, поставьте в файле `env_overrides: false`.

Можно использовать и оригинальный generic-rust egg: укажите `GIT_ADDRESS=https://github.com/amper24/AmperverserDnD-Table`, а в Startup Configuration → done: `Server listening on`.

### Linux / macOS
```bash
./run.sh          # соберёт через cargo (нужен Rust: https://rustup.rs) или запустит ./dnd-table из Releases
```

### Windows
Без Rust — `install.bat`: скачает `dnd-table-windows-x86_64.exe` из **последнего** релиза, положит его рядом с собой как `dnd-table.exe`, подложит `run.bat` и запустит сервер. Запустите ещё раз, чтобы обновиться до свежего релиза.

```bat
run.bat                 :: двойной клик или из cmd: dnd-table.exe рядом -> target\release -> сборка через cargo
run.bat help            :: аргументы передаются бинарнику (users list, users make-root <email>, stats)
install.bat             :: скачать готовый .exe из GitHub Releases и запустить
```
Установка в другую папку и без паузы в конце:
```bat
set DND_DIR=D:\dnd && set NO_PAUSE=1 && install.bat
```
Одной строкой (без клона репозитория) — скачиваем `install.bat` и запускаем:
```powershell
curl.exe -L -o install.bat https://raw.githubusercontent.com/amper24/AmperverserDnD-Table/main/install.bat; .\install.bat
```

Переменные: `PORT` (8080), `NO_BROWSER=1` — не открывать браузер, `NO_PAUSE=1` — не ждать клавишу в конце (используется в CI), `REBUILD=1` — пересобрать через cargo, `DND_DIR` — куда ставить (по умолчанию папка скрипта), `DND_URL` — откуда качать `dnd-table.exe` (зеркало, приватная сборка), `DND_RUN_URL` — откуда качать `run.bat`, если его нет рядом с `install.bat`.

`install.bat` качает в `dnd-table.exe.new` и подменяет файл только после успешной загрузки: при обрыве сети/прокси или занятом (запущенном) `dnd-table.exe` прежняя версия остаётся на месте. Слишком маленький файл (HTML-заглушка прокси/антивируса) отсекается проверкой размера. Суммы SHA-256 всех файлов релиза — в `SHA256SUMS.txt` на странице релиза.

Если `run.bat` печатает мусор вроде `'.' is not recognized…`, `'EXE' is not recognized…`, `'и' is not recognized…` — это cmd разбирает файл в неправильной кодировке / с неправильными переводами строк (батник был в UTF-8 с кириллицей и с LF). Сейчас `*.bat` в репозитории ASCII-only и с CRLF, это фиксирует `.gitattributes`. На уже испорченной копии: `git pull`, затем `git rm --cached run.bat install.bat && git checkout -- run.bat install.bat` (или просто свежий клон) — и батники пересохранятся с CRLF.

## Настройка (`config.yml`)

При первом запуске рядом с программой (в текущем каталоге) создаётся **`config.yml`** — в нём с комментариями собраны все важные параметры. Отредактируйте его и перезапустите сервер.

```yaml
env_overrides: true          # false — игнорировать переменные окружения (кроме SERVER_PORT)
server:   { host: "0.0.0.0", port: 8080 }
database: { url: "sqlite://data/dnd.db", max_connections: 10 }
smtp:     { host: "", port: 587, encryption: "auto", user: "", password: "", from: "noreply@example.com" }
auth:     { allow_registration: true, dev_show_code: true, code_ttl_minutes: 10, code_max_attempts: 5, session_days: 30, password_min_length: 8 }
root:     { email: "", password: "" }
images:   { quality: 82, max_upload_mb: 25, map_max_side: 4096, token_max_side: 1024 }
logging:  { level: "info,sqlx=warn" }
```
(в самом файле — развёрнутый вид с пояснением к каждой строке)

* **Где лежит:** `./config.yml`; другой путь — `dnd-table --config /путь/config.yml` или переменная `DND_CONFIG` (в Docker — `/app/data/config.yml`).
* **Приоритет:** значения по умолчанию → `config.yml` → переменные окружения и `.env`. Пустая переменная считается незаданной. Если панель хостинга всегда передаёт свои переменные (Pterodactyl), поставьте `env_overrides: false` — тогда всё берётся из файла, кроме порта панели `SERVER_PORT`. Какие параметры перекрыты переменными, сервер пишет в лог при старте.
* **Проверить:** команда `config` в консоли сервера (или `dnd-table config`) — путь к файлу, источники значений и действующие настройки (пароли скрыты).
* **Обновления:** если в новой версии появились параметры, сервер сам допишет их в `config.yml` (ваши значения сохраняются), а прежний файл положит рядом как `config.yml.bak`. Опечатки в именах параметров выводятся в лог предупреждением; значения вне допустимого диапазона исправляются с предупреждением. Ошибка синтаксиса YAML останавливает запуск с номером строки.
* `config.yml` содержит пароли — он в `.gitignore`, не коммитьте его.

| Параметр `config.yml` | Переменная | Описание |
|---|---|---|
| `server.host`, `server.port` | `HOST`, `PORT` / `SERVER_PORT` | адрес и порт (0.0.0.0 / 8080) |
| `database.url` | `DATABASE_URL` | `mysql://user:pass@host:3306/db` или `sqlite://data/dnd.db` |
| `database.max_connections` | `DB_MAX_CONNECTIONS` | пул соединений MySQL (SQLite — всегда 1) |
| `smtp.host/port/user/password/from` | `SMTP_HOST/PORT/USER/PASSWORD/FROM` | почта для кодов. Если `host` пуст — код печатается в консоль |
| `smtp.encryption` | `SMTP_ENCRYPTION` | `auto` (465 → TLS, иначе STARTTLS), `starttls`, `tls`, `none` |
| `auth.allow_registration` | `ALLOW_REGISTRATION` | `false` — регистрация через сайт закрыта, аккаунты создаёт root |
| `auth.dev_show_code` | `DEV_SHOW_CODE` | `true` — без SMTP код возвращается в ответе API и подставляется в форму (только для разработки!) |
| `auth.code_ttl_minutes`, `auth.code_max_attempts` | `CODE_TTL_MINUTES`, `CODE_MAX_ATTEMPTS` | срок жизни кода из письма и число попыток ввода |
| `auth.session_days` | `SESSION_DAYS` | срок жизни сессии в днях (0 — без ограничения) |
| `auth.password_min_length` | `PASSWORD_MIN_LENGTH` | минимальная длина пароля в веб-формах |
| `root.email`, `root.password` | `ROOT_EMAIL`, `ROOT_PASSWORD` | автосоздание root-аккаунта при старте (см. «Root и CLI»). Если пользователь с такой почтой уже есть — он не меняется |
| `images.quality` | `IMAGE_QUALITY` | качество JPEG при сжатии картинок (82) |
| `images.max_upload_mb` | `MAX_UPLOAD_MB` | максимальный размер загружаемого файла, МБ (25) |
| `images.map_max_side`, `images.token_max_side` | `MAP_MAX_SIDE`, `TOKEN_MAX_SIDE` | до какой стороны уменьшаются карты и остальные картинки (4096 / 1024) |
| `logging.level` | `RUST_LOG` | уровень логов (`info,sqlx=warn`) |

## Авторизация

Регистрация: почта + пароль (argon2) + имя → на почту приходит 6-значный код подтверждения. Вход — по паролю; «Забыли пароль?» — новый пароль по коду из письма (так же можно задать пароль старому аккаунту без него). Без настроенного SMTP код печатается в консоль сервера и (при `DEV_SHOW_CODE=true`) показывается прямо в форме. Сессия — HttpOnly-cookie (`SameSite=Lax`, плюс дубликат `SameSite=None; Secure; Partitioned` для встраивания по HTTPS) и Bearer-токен в `localStorage` как запасной канал; в URL токен никогда не попадает. Страница `/diag` показывает, что именно блокирует браузер, если вход не держится. Под Google OAuth зарезервированы поле `users.google_sub`, маршрут `/api/auth/google` и кнопка на главной.

## Как пользоваться
1. Войдите, создайте кампанию — вы её **мастер**.
2. ⚙ *Настройки* → ссылка-приглашение (для игроков или второго мастера).
3. 🖼 *Ассеты*: перетащите свои картинки (карты, токены). Они ресайзятся, кодируются (JPEG/PNG), сжимаются deflate и хранятся в БД в base64; браузер распаковывает их сам через `DecompressionStream`. Есть 30 встроенных ассетов.
4. Перетаскивайте ассеты на стол (или двойной клик — в центр). Слой карты — через список «Слой» вверху.
5. 🧙 *Персонажи*: создайте лист, перетащите персонажа на стол — появится связанный токен. Двойной клик по токену открывает лист **поверх стола**; кнопка ⧉ — **в отдельном окне браузера**.
6. 📚 *Справочник*: перетаскивайте расы/классы/предметы/заклинания на лист персонажа (бонусы применяются автоматически), монстров — на стол (токен с хитами и статблоком, из статблока — броски атак/урона прямо в чат). Мастер может добавлять свои записи (homebrew). Свои расы, классы и предыстории создаются с готовыми блоками параметров (бонусы характеристик, кость хитов, навыки, владения) и могут предлагать игроку выбор «либо / либо» при создании персонажа; токена на карте у классов и рас нет.
7. Инструменты: выбор (V), панорама (H / пробел / ПКМ по пустому месту), линейка (R, видят все), рисование (D), текст, указка (P), туман войны (F, мастер). **ПКМ по токену — контекстное меню** (урон/лечение, дублировать, скрыть, закрепить, слои). Delete — удалить, стрелки — сдвиг на клетку, Ctrl+C/V — копия.
8. Сетка: квадраты или **гексы**, размер, масштаб (фт), цвет — в панели 🗺 *Сцены*.
9. 💬 Чат: `/r 2d20kh1+5`, кнопки кубиков, скрытые броски мастера. ⚔ Инициатива: «Собрать со стола».
10. Мастер переключает сцены; «👁 Показать» назначает активную сцену игрокам.

## Стол: создание и кубики

- Кнопка **«Создать»** в верхней панели стола: персонаж (лист + токен в центре экрана), NPC/монстр-токен (имя, хиты, размер, скрыт от игроков), предмет (на стол как лут / в инвентарь персонажа / в homebrew-справочник кампании), заклинание (персонажу / в справочник), любая запись справочника, новая сцена, импорт из Long Story Short.
- **Кубики** — всегда под рукой: док слева внизу (к4–к100, режим обычно/преимущество/помеха для к20, модификатор, своя формула `2d6+3` / `4d6kh3`, у мастера — «скрытый» бросок; Shift+клик — бросить дважды; док сворачивается в одну кнопку). Справа внизу — **журнал** ваших бросков (повтор, очистка, настройки). Результат — всплывающая карточка снизу: появилась, показалась и сама ушла, закрывать не нужно. Кости объёмные, **числа нарисованы на гранях**, а кубик доворачивается к вам той гранью, которая выпала. Результаты уходят в чат всем участникам.

## Импорт из Long Story Short

Кнопка **«Импорт из Long Story Short»** в разделе «Персонажи», в панели «Персонажи» на столе и в меню «Создать». Принимает `.json`, который выгружает LSS (longstoryshort.app → лист → «Экспорт»). Переносятся: имя, раса, класс/уровень, предыстория, мировоззрение, опыт, характеристики, владения спасбросками и навыками (включая компетентность), хиты/КД/скорость/кость хитов, монеты, интерактивные атаки (`weaponsList`), снаряжение и предметы (строки превращаются в предметы инвентаря с количеством и типом), черты/умения/ресурсы (в «Умения»), заклинания по уровням (сопоставляются со справочником по названию; ненайденные — пустыми карточками), ячейки заклинаний, характеристика заклинателя, личность/идеалы/привязанности/слабости, владения, предыстория и заметки. Портрет не переносится (в уведомлении показывается ссылка). Импорт полностью на клиенте: `static/lss.js`.

## Предметы, заклинания, кнопки бросков

Предметы и заклинания — не текст, а **модули**: карточки с иконкой, редкостью, зарядами и кнопками бросков. Их можно:

- перетаскивать из справочника на лист, между листами разных персонажей (через окна/iframe), на персонажа в панели «Персонажи» (передача) и **на стол** — появится токен-лут, который любой игрок может «Подобрать» через ПКМ;
- отправлять в чат карточкой (`💬 В чат`) — кнопки бросков работают прямо в чате у всех;
- редактировать в визуальном редакторе: поля + конструктор действий (атака/урон/лечение/спасбросок) без JSON; есть библиотека шаблонов — «Атака → урон», «Зелье → хиты → флакон», «Спасбросок → урон», бонусы характеристик, владения и другие цепочки;
- атаку показывать как на листах: **две кнопки — попадание и урон** (плюс кнопка всей цепочки с расходом и эффектами).

**Синтаксис кнопок в любом тексте** (описания предметов, заклинаний, умений, справочника, чата):

| Пишете | Получаете |
|---|---|
| `[[1d20+@atk]]{Атака}` | кнопка «Атака», бросает d20 + лучший модификатор атаки + мастерство |
| `[[2к6+@str]]` | кнопка с формулой (русская «к» тоже понимается) |
| просто `3к6+2` в тексте | автоматически подсвечивается как кнопка |

Переменные: `@str @dex @con @int @wis @cha` (модификаторы), `@prof`, `@level`, `@atk` / `@atk_str` / `@atk_dex`, `@spell` (бонус атаки заклинанием), `@dc` (СЛ заклинаний), `@ac`, `@hp`, `@init`, `@best` (макс. из Сил/Лов). Shift+клик по кнопке — скрытый бросок мастера.

## Cookie, согласие и конфиденциальность

При первом заходе показывается баннер согласия: «Принять все» / «Только обязательные» / «Настроить». Категории:
- **Обязательные** (всегда): `dnd_session` и `dnd_session_x` — cookie сессии (HttpOnly, 30 дней; второй с `SameSite=None; Secure; Partitioned` для работы во фрейме), `dnd_token` — копия токена в localStorage для запросов/WebSocket без cookie, `et-consent` — сам выбор (1 год).
- **Функциональные** (по согласию): `et-theme`, `sheet_tab_*`, `dicetray_min`. Без согласия эти ключи не пишутся в localStorage (живут в памяти до перезагрузки), при отзыве согласия — удаляются.
- Аналитики и рекламных cookie нет.

Страница `/privacy` — политика конфиденциальности с таблицей всех cookie/ключей и правами пользователя; кнопка «Настройки cookie» есть внизу главной, в профиле и на `/privacy`. Владелец сервера может дополнить текст в `static/app.js` (`renderPrivacy`).

## Наборы (packs)

Свои коллекции записей справочника. Вкладка **«Наборы»** в лобби: создать, импорт/экспорт JSON, публичность. Свои наборы всегда видны владельцу; мастер подключает наборы к кампании в **Настройках** — и они появляются у всех игроков. Любую запись (в т.ч. базовую SRD) можно «Копировать в набор» и там править. Сами базовые записи может менять только root (см. «Root и CLI»).

## Права
- **Root** (администратор сервера): всё ниже, плюс редактирование базового справочника и любых наборов, встроенные ассеты, управление пользователями (`/admin`). Права хранятся во флаге `users.is_root`, выдаются только через CLI или переменные окружения — из интерфейса root может назначить других root.
- **Мастер**: всё — скрытые элементы, туман, слои, сцены, приглашения, роли, homebrew.
- **Игрок**: видит активную сцену без скрытых элементов и скрытых бросков; двигает только свои токены (владелец назначается мастером или создаётся при перетаскивании своего персонажа); рисует, измеряет, пишет в чат; редактирует своих персонажей.

## Root и CLI

**Root** — администратор сервера. Может:
- редактировать и удалять записи **базового справочника** (SRD) и создавать новые базовые записи — в разделе «Справочник» у root появляются кнопки «Редактировать»/«Удалить» на любых записях, а в «Копировать в набор…» и «Новая запись» — пункт «Базовый справочник (root)»;
- редактировать **любые наборы** (packs) других пользователей;
- загружать **встроенные ассеты** (галочка «как встроенный» в Библиотеке ресурсов — видны всем пользователям) и удалять любые ассеты;
- управлять пользователями на странице **`/admin`** (пункт «Админ» в шапке): создать, переименовать, сменить пароль, выдать/снять root, удалить; смотреть статистику базы; пересоздать базовый справочник из вшитого seed.

Из веб-интерфейса снять root с единственного администратора нельзя (через консоль/CLI — можно, сервер предупредит); удалить самого себя — тоже.

### Как получить root

Вариант 1 — `config.yml` (или переменные окружения `ROOT_EMAIL` / `ROOT_PASSWORD` — удобно для Docker и Pterodactyl):
```yaml
root:
  email: "admin@example.com"
  password: "очень-секретно"   # лучше 8+ символов: короткий пароль сервер примет, но предупредит в логе
```
При старте сервер создаст подтверждённый аккаунт с root. Если аккаунт с такой почтой уже есть, сервер его не трогает (в лог выводится подсказка) — права выдаются командой `users make-root`. Пароль потом можно убрать из файла — флаг сохраняется в БД.

Вариант 2 — консоль сервера (Pterodactyl, `docker attach`, терминал с `run.sh`): пока сервер работает, команды вводятся прямо в его консоль — как есть или с префиксом `dnd-table`, как в этой документации:
```
help
users list
users make-root admin@example.com
dnd-table users create admin@example.com secret123 --root
stop
```

Вариант 3 — CLI отдельным процессом (бинарник тот же, что и сервер; нужен доступ к той же `DATABASE_URL`):
```
dnd-table users create admin@example.com secret123 --name Админ --root
dnd-table users make-root admin@example.com
```

Без пароля команда спросит его сама (ввод не отображается в терминале); в консоли сервера пароль передаётся аргументом.

### Команды CLI

Все команды используют базу из `config.yml` (`database.url`) или `DATABASE_URL` из окружения/`.env` (по умолчанию `sqlite://data/dnd.db`). Их можно выполнять при работающем сервере. Другой файл конфигурации — `--config <файл>` в любом месте командной строки.

| Команда | Что делает |
|---|---|
| `dnd-table` / `dnd-table serve` | запустить сервер |
| `dnd-table users list [--json]` | список пользователей (почта, имя, root, подтверждение почты, дата) |
| `dnd-table users show <email> [--json]` | подробности аккаунта: id, кампании (владелец/участник), персонажи, наборы, сессии |
| `dnd-table users create <email> [пароль] [--name <имя>] [--root]` | создать подтверждённого пользователя (с `--root` — администратора) |
| `dnd-table users set-password <email> [пароль]` | сменить пароль и завершить все сессии пользователя |
| `dnd-table users rename <email> <имя>` | сменить отображаемое имя |
| `dnd-table users make-root <email>` | выдать права root |
| `dnd-table users revoke-root <email>` | снять права root (если это последний root — сервер предупредит) |
| `dnd-table users delete <email> [--yes]` | удалить пользователя вместе с его кампаниями, персонажами, наборами и ресурсами |
| `dnd-table stats [--json]` | сводка: пользователи (и сколько root), кампании, персонажи, ассеты, базовый справочник, наборы |
| `dnd-table reseed [--yes]` | удалить базовые записи справочника и залить их заново из вшитого seed (правки root в базовых записях теряются; наборы и homebrew не трогаются) |
| `dnd-table config` | путь к `config.yml`, какие параметры перекрыты переменными окружения, действующие настройки (пароли скрыты) |
| `dnd-table help [команда]` | справка (например, `dnd-table help users create`), `dnd-table version` — версия бинарника |
| `stop` (только в консоли сервера) | остановить сервер |

Что стоит знать:

* флаги можно писать как `--name Иван`, `--name=Иван` или `-n Иван` — в любом месте команды;
* если пароль не указан и команда запущена в терминале, она спросит его сама (ввод не отображается); для скриптов есть `--password <пароль>`;
* короткий пароль (меньше 8 символов) CLI создаёт, но предупреждает: веб-форма такой пароль не принимает, а аккаунт доступен из сети;
* почта должна иметь вид `name@domain.tld` — по этой же почте выполняется вход в веб-интерфейс;
* коды возврата: `0` — успех, `1` — ошибка выполнения, `2` — неверная команда/флаги; сообщения печатаются в stderr и всегда сопровождаются подсказкой;
* те же команды понимает консоль запущенного сервера — с префиксом `dnd-table` или без него (удобно на Pterodactyl, где терминала с `cargo` нет);
* удаление пользователя чистит и «хвосты»: его ассеты, подписки на наборы, участия в кампаниях и сессии.

### Admin API (для root)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/admin/users` | список пользователей |
| POST | `/api/admin/users` | `{email, password, name?, is_root?}` — создать |
| PATCH | `/api/admin/users/:id` | `{name?, is_root?, password?, verified?}` |
| DELETE | `/api/admin/users/:id` | удалить |
| GET | `/api/admin/stats` | статистика |
| POST | `/api/admin/reseed` | пересоздать базовый справочник |

Кроме того, для root снимаются ограничения в обычных API: `PATCH/DELETE /api/compendium/:id` на базовых записях, `POST /api/compendium` без `campaign_id`/`pack_id` (запись попадает в базовый справочник с источником `SRD`), `POST /api/assets` с полем `builtin=1`, `DELETE /api/assets/:id` для любых ассетов, любые операции с чужими наборами.

## Сборки и релизы

Три workflow-джоба в `.github/workflows/`:

| Что | Когда | Результат |
|---|---|---|
| `ci.yml` → `build-test` | push в любую ветку, PR, тег | сборка + smoke-тесты на SQLite и MySQL, артефакт `dnd-table-linux-x86_64` |
| `ci.yml` → `windows` | push, PR, тег | сборка под Windows, прогон `run.bat` (CLI и сервер) и `install.bat` (скачивание ассета + запуск). В **каждом pull request** публикуется артефакт **`dnd-table.exe`** — его можно скачать в Actions → нужный run → Artifacts |
| `release.yml` → `binaries` + `publish` | push тега `v*` | бинарники Linux/Windows/macOS + `run.bat`/`install.bat`/`SHA256SUMS.txt` → GitHub Release |

**Выпустить релиз** (версия тега должна совпадать с `version` в `Cargo.toml`, иначе джоб печатает предупреждение):

```bash
git tag v0.4.6 && git push origin v0.4.6
```

Имена ассетов — публичный контракт (на них завязаны `install.bat`, `install.sh` и раздел «Windows» выше):

```
dnd-table-windows-x86_64.exe   ← install.bat (install.bat / run.bat)
dnd-table-linux-x86_64         ← install.sh, /releases/latest/download/...
dnd-table-macos-aarch64        ← install.sh
run.bat · install.bat · SHA256SUMS.txt
```

Меняя имя ассета, поправьте `install.bat` (`set "REL=..."`, `DND_URL`), `install.sh` (`ASSET`) и таблицу в `release.yml`. Тег без префикса `v` (например `0.2.0`) бинарников не публикует.
