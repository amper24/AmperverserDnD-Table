# Edge Tablet (Amperverser DnD Table)

Виртуальный стол для D&D 5e в духе Owlbear Rodeo: кампании, приглашения по ссылке, роли **мастер/игрок**, сцены с картами и токенами, туман войны, линейка, рисование, чат с кубиками, инициатива, листы персонажей и справочник на русском (расы, классы, предыстории, предметы, заклинания, бестиарий, черты, состояния).

**Стек:** Rust (axum · tokio · sqlx) · **MySQL** или SQLite · WebSocket · фронтенд на чистом JS/Canvas, встроен в бинарник. Один исполняемый файл, без внешних зависимостей.

## Быстрый старт

### Одной командой
```bash
curl -fsSL https://raw.githubusercontent.com/amper24/AmperverserDnD-Table/main/install.sh | bash
```
Сам выбирает способ: Docker (с MySQL) → cargo → готовый бинарник из Releases. Переменные: `DND_DIR`, `DND_MODE=docker|cargo|binary`, `PORT`.

### Docker Compose (MySQL + приложение)
```bash
cp .env.example .env
docker compose up -d --build
```

### Pterodactyl (generic Rust egg)
Импортируйте `deploy/pterodactyl-egg.json` (Admin → Nests → Import Egg) — это стандартный [generic-rust](https://eggs.pterodactyl.io/egg/generic-rust-generic/) egg с преднастроенным репозиторием и переменными (`DATABASE_URL`, SMTP). Старт: `cargo run --release`; порт берётся из `SERVER_PORT` автоматически; строка готовности — `Server listening on`.

Можно использовать и оригинальный generic-rust egg: укажите `GIT_ADDRESS=https://github.com/amper24/AmperverserDnD-Table`, а в Startup Configuration → done: `Server listening on`.

### Linux / macOS
```bash
./run.sh          # соберёт через cargo (нужен Rust: https://rustup.rs) или запустит ./dnd-table из Releases
```

### Windows
Запустите `run.bat` (нужен Rust с rustup.rs **или** `dnd-table.exe` из Releases рядом со скриптом).

## Настройка (`.env` или переменные окружения)
| Переменная | Описание |
|---|---|
| `DATABASE_URL` | `mysql://user:pass@host:3306/db` или `sqlite://data/dnd.db` (по умолчанию) |
| `PORT`, `HOST` | порт/адрес (8080 / 0.0.0.0). На Pterodactyl используется `SERVER_PORT` |
| `SMTP_HOST/PORT/USER/PASSWORD/FROM` | почта для кодов входа. Если `SMTP_HOST` пуст — код печатается в консоль |
| `DEV_SHOW_CODE` | `true` — код также возвращается в ответе API и подставляется в форму (только для разработки!) |
| `IMAGE_QUALITY` | качество JPEG при сжатии картинок (82) |
| `ROOT_EMAIL`, `ROOT_PASSWORD` | автосоздание root-аккаунта при старте (см. «Root и CLI»). Если пользователь с такой почтой уже есть — ему выдаётся root |
| `RUST_LOG` | уровень логов (`info,sqlx=warn`) |

## Авторизация

Регистрация: почта + пароль (argon2) + имя → на почту приходит 6-значный код подтверждения. Вход — по паролю; «Забыли пароль?» — новый пароль по коду из письма (так же можно задать пароль старому аккаунту без него). Без настроенного SMTP код печатается в консоль сервера и (при `DEV_SHOW_CODE=true`) показывается прямо в форме. Сессия — HttpOnly-cookie (`SameSite=Lax`, плюс дубликат `SameSite=None; Secure; Partitioned` для встраивания по HTTPS) и Bearer-токен в `localStorage` как запасной канал; в URL токен никогда не попадает. Страница `/diag` показывает, что именно блокирует браузер, если вход не держится. Под Google OAuth зарезервированы поле `users.google_sub`, маршрут `/api/auth/google` и кнопка на главной.

## Как пользоваться
1. Войдите, создайте кампанию — вы её **мастер**.
2. ⚙ *Настройки* → ссылка-приглашение (для игроков или второго мастера).
3. 🖼 *Ассеты*: перетащите свои картинки (карты, токены). Они ресайзятся, кодируются (JPEG/PNG), сжимаются deflate и хранятся в БД в base64; браузер распаковывает их сам через `DecompressionStream`. Есть 30 встроенных ассетов.
4. Перетаскивайте ассеты на стол (или двойной клик — в центр). Слой карты — через список «Слой» вверху.
5. 🧙 *Персонажи*: создайте лист, перетащите персонажа на стол — появится связанный токен. Двойной клик по токену открывает лист **поверх стола**; кнопка ⧉ — **в отдельном окне браузера**.
6. 📚 *Справочник*: перетаскивайте расы/классы/предметы/заклинания на лист персонажа (бонусы применяются автоматически), монстров — на стол (токен с хитами и статблоком, из статблока — броски атак/урона прямо в чат). Мастер может добавлять свои записи (homebrew).
7. Инструменты: выбор (V), панорама (H / пробел / ПКМ по пустому месту), линейка (R, видят все), рисование (D), текст, указка (P), туман войны (F, мастер). **ПКМ по токену — контекстное меню** (урон/лечение, дублировать, скрыть, закрепить, слои). Delete — удалить, стрелки — сдвиг на клетку, Ctrl+C/V — копия.
8. Сетка: квадраты или **гексы**, размер, масштаб (фт), цвет — в панели 🗺 *Сцены*.
9. 💬 Чат: `/r 2d20kh1+5`, кнопки кубиков, скрытые броски мастера. ⚔ Инициатива: «Собрать со стола».
10. Мастер переключает сцены; «👁 Показать» назначает активную сцену игрокам.

## Стол: создание и кубики

- Кнопка **«Создать»** в верхней панели стола: персонаж (лист + токен в центре экрана), NPC/монстр-токен (имя, хиты, размер, скрыт от игроков), предмет (на стол как лут / в инвентарь персонажа / в homebrew-справочник кампании), заклинание (персонажу / в справочник), любая запись справочника, новая сцена, импорт из Long Story Short.
- **Панель кубиков** внизу стола: к4–к100, режим обычно/преимущество/помеха для к20, поле модификатора, своя формула (`2d6+3`, `4d6kh3`), у мастера — «скрытый» бросок. Результаты уходят в чат всем участникам. Shift+клик — бросить дважды. Панель сворачивается кнопкой слева.

## Импорт из Long Story Short

Кнопка **«Импорт из Long Story Short»** в разделе «Персонажи», в панели «Персонажи» на столе и в меню «Создать». Принимает `.json`, который выгружает LSS (longstoryshort.app → лист → «Экспорт»). Переносятся: имя, раса, класс/уровень, предыстория, мировоззрение, опыт, характеристики, владения спасбросками и навыками (включая компетентность), хиты/КД/скорость/кость хитов, монеты, интерактивные атаки (`weaponsList`), снаряжение и предметы (строки превращаются в предметы инвентаря с количеством и типом), черты/умения/ресурсы (в «Умения»), заклинания по уровням (сопоставляются со справочником по названию; ненайденные — пустыми карточками), ячейки заклинаний, характеристика заклинателя, личность/идеалы/привязанности/слабости, владения, предыстория и заметки. Портрет не переносится (в уведомлении показывается ссылка). Импорт полностью на клиенте: `static/lss.js`.

## Предметы, заклинания, кнопки бросков

Предметы и заклинания — не текст, а **модули**: карточки с иконкой, редкостью, зарядами и кнопками бросков. Их можно:

- перетаскивать из справочника на лист, между листами разных персонажей (через окна/iframe), на персонажа в панели «Персонажи» (передача) и **на стол** — появится токен-лут, который любой игрок может «Подобрать» через ПКМ;
- отправлять в чат карточкой (`💬 В чат`) — кнопки бросков работают прямо в чате у всех;
- редактировать в визуальном редакторе: поля + конструктор действий (атака/урон/лечение/спасбросок) без JSON.

**Синтаксис кнопок в любом тексте** (описания предметов, заклинаний, умений, справочника, чата):

| Пишете | Получаете |
|---|---|
| `[[1d20+@atk]]{Атака}` | кнопка «Атака», бросает d20 + лучший модификатор атаки + мастерство |
| `[[2к6+@str]]` | кнопка с формулой (русская «к» тоже понимается) |
| просто `3к6+2` в тексте | автоматически подсвечивается как кнопка |

Переменные: `@str @dex @con @int @wis @cha` (модификаторы), `@prof`, `@level`, `@atk` / `@atk_str` / `@atk_dex`, `@spell` (бонус атаки заклинанием), `@dc` (СЛ заклинаний), `@ac`, `@hp`, `@init`, `@best` (макс. из Сил/Лов). Shift+клик по кнопке — скрытый бросок мастера.

## Cookie, согласие и конфиденциальность

При первом заходе показывается баннер согласия: «Принять все» / «Только обязательные» / «Настроить». Категории:
- **Обязательные** (всегда): `dnd_session` и `dnd_session_x` — cookie сессии (HttpOnly, 30 дней; второй с `SameSite=None; Secure; Partitioned` для работы во фрейме), `dnd_token` — копия токена в localStorage для запросов/WebSocket без cookie, `et-consent` — сам выбор (1 год).
- **Функциональные** (по согласию): `et-theme`, `sheet_tab_*`, `dicetray_min`. Без согласия эти ключи не пишутся в localStorage (живут в памяти до перезагрузки), при отзыве согласия — удаляются.
- Аналитики и рекламных cookie нет.

Страница `/privacy` — политика конфиденциальности с таблицей всех cookie/ключей и правами пользователя; кнопка «Настройки cookie» есть внизу главной, в профиле и на `/privacy`. Владелец сервера может дополнить текст в `static/app.js` (`renderPrivacy`).

## Наборы (packs)

Свои коллекции записей справочника. Вкладка **«Наборы»** в лобби: создать, импорт/экспорт JSON, публичность. Свои наборы всегда видны владельцу; мастер подключает наборы к кампании в **Настройках** — и они появляются у всех игроков. Любую запись (в т.ч. базовую SRD) можно «Копировать в набор» и там править. Сами базовые записи может менять только root (см. «Root и CLI»).

## Права
- **Root** (администратор сервера): всё ниже, плюс редактирование базового справочника и любых наборов, встроенные ассеты, управление пользователями (`/admin`). Права хранятся во флаге `users.is_root`, выдаются только через CLI или переменные окружения — из интерфейса root может назначить других root.
- **Мастер**: всё — скрытые элементы, туман, слои, сцены, приглашения, роли, homebrew.
- **Игрок**: видит активную сцену без скрытых элементов и скрытых бросков; двигает только свои токены (владелец назначается мастером или создаётся при перетаскивании своего персонажа); рисует, измеряет, пишет в чат; редактирует своих персонажей.

## Root и CLI

**Root** — администратор сервера. Может:
- редактировать и удалять записи **базового справочника** (SRD) и создавать новые базовые записи — в разделе «Справочник» у root появляются кнопки «Редактировать»/«Удалить» на любых записях, а в «Копировать в набор…» и «Новая запись» — пункт «Базовый справочник (root)»;
- редактировать **любые наборы** (packs) других пользователей;
- загружать **встроенные ассеты** (галочка «как встроенный» в Библиотеке ресурсов — видны всем пользователям) и удалять любые ассеты;
- управлять пользователями на странице **`/admin`** (пункт «Админ» в шапке): создать, переименовать, сменить пароль, выдать/снять root, удалить; смотреть статистику базы; пересоздать базовый справочник из вшитого seed.

Снять root с единственного администратора нельзя; удалить самого себя — тоже.

### Как получить root

Вариант 1 — переменные окружения (удобно для Docker и Pterodactyl):
```
ROOT_EMAIL=admin@example.com
ROOT_PASSWORD=очень-секретно   # минимум 8 символов
```
При старте сервер создаст подтверждённый аккаунт с root (или выдаст root уже существующему пользователю с этой почтой и обновит ему пароль). Переменные можно потом убрать — флаг сохраняется в БД.

Вариант 2 — CLI (бинарник тот же, что и сервер; нужен доступ к той же `DATABASE_URL`):
```
dnd-table users make-root admin@example.com
```

### Команды CLI

Все команды используют `DATABASE_URL` из окружения/`.env` (по умолчанию `sqlite://data/dnd.db`). Их можно выполнять при работающем сервере.

| Команда | Что делает |
|---|---|
| `dnd-table` / `dnd-table serve` | запустить сервер |
| `dnd-table users list` | список пользователей (почта, имя, root, подтверждён, дата) |
| `dnd-table users create <email> <пароль> [--name <имя>] [--root]` | создать подтверждённого пользователя (с `--root` — администратора) |
| `dnd-table users make-root <email>` | выдать права root |
| `dnd-table users revoke-root <email>` | снять права root (единственного root снять нельзя) |
| `dnd-table users set-password <email> <пароль>` | сменить пароль и завершить все сессии пользователя |
| `dnd-table users delete <email>` | удалить пользователя вместе с его кампаниями, персонажами и наборами |
| `dnd-table stats` | сводка: пользователи, кампании, персонажи, ассеты, базовый справочник, наборы |
| `dnd-table reseed` | удалить базовые записи справочника и залить их заново из вшитого seed (правки root в базовых записях теряются; наборы и homebrew не трогаются) |
| `dnd-table help` | справка |

Как запускать в разных окружениях:
```bash
# собранный бинарник
./target/release/dnd-table users list

# через cargo (например, на Pterodactyl в консоли сервера)
cargo run --release -- users make-root admin@example.com

# Docker Compose
docker compose exec app dnd-table users create admin@example.com secret123 --name Admin --root

# другая БД
DATABASE_URL="mysql://dnd:dnd@localhost:3306/dnd" dnd-table stats
```

### Admin API (для root)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/admin/users` | список пользователей |
| POST | `/api/admin/users` | `{email, password, name?, is_root?}` — создать |
| PATCH | `/api/admin/users/:id` | `{name?, is_root?, password?, verified?}` |
| DELETE | `/api/admin/users/:id` | удалить |
| GET | `/api/admin/stats` | статистика |
| POST | `/api/admin/reseed` | пересоздать базовый справочник |

Кроме того, для root снимаются ограничения в обычных API: `PATCH/DELETE /api/compendium/:id` на базовых записях, `POST /api/compendium` без `campaign_id`/`pack_id` (запись попадает в базовый справочник с источником `SRD`), `POST /api/assets` с полем `builtin=1`, `DELETE /api/assets/:id` для любых ассетов, любые операции с чужими наборами.

## Структура
```
Cargo.toml              # в корне — как требует Pterodactyl generic-rust egg
src/
  main.rs               # axum-роутер, встроенная статика (rust-embed)
  config.rs db.rs       # .env, схема БД (MySQL/SQLite через sqlx Any)
  auth.rs               # коды на почту (lettre), сессии, экстрактор AuthUser
  campaigns.rs scenes.rs assets.rs characters.rs compendium.rs
  realtime.rs           # WebSocket-хаб: стол, чат, броски, права игрок/мастер
  images.rs             # ресайз → JPEG/PNG → zlib → base64
  seed.rs               # справочник и встроенные ассеты из data_seed/ (вшиты в бинарник)
static/                 # index.html, app.js (лобби+кампания), table.js (canvas-стол), sheet.js, compendium.js
data_seed/              # compendium.json (191 запись SRD, рус.), builtin/ (30 ассетов)
scripts/smoke.sh        # сквозной API/WS-тест (гоняется в CI на SQLite и MySQL 8.4)
deploy/pterodactyl-egg.json · Dockerfile · docker-compose.yml · run.sh · run.bat · install.sh
```

## Разработка
```bash
cargo run                       # SQLite в data/dnd.db, http://localhost:8080
DATABASE_URL=mysql://dnd:dnd@localhost/dnd cargo run
bash scripts/smoke.sh target/debug/dnd-table   # сквозной тест (нужны python3, websockets)
```
Релиз: тег `vX.Y.Z` → CI собирает бинарники для Linux/Windows/macOS и публикует в Releases.
