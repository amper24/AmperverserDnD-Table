### 1.2 Что проверено по источнику

* Машинно-сопоставимые поля сверены с дампом SRD: **10 497 сверок, 0 расхождений** —
  заклинания (уровень, концентрация, ритуал, классы, кости и типы урона), монстры

* Русские тексты — не перевод «своими словами»: базовый язык набора русский, английский

* Инварианты структуры: уникальность `(категория, слаг)`, совпадение `data.edition` с
  набором, ссылки между сущностями (классы заклинаний, подрасы, подклассы, заклинания и

## 2. Что исправлено

1. **Терминология навыков.** `tools/srd/ru_names.py` приведён к словарю листа
   («Investigation → Расследование»), в данных 43 замены. Скрипт `tools/srd/fix_skill_names.py`
   идемпотентен и падает с кодом 1, если название навыка класса не найдено в `window.SKILLS`.
   Старое написание «Анализ» осталось только как алиас для чтения прежних текстов
   (`tools/srd/i18n_terms.py`, `static/character-builder.js`).
2. **Английские типы урона.** `tools/srd/fix_en_damage_types.py` заполняет `dtype` в
   `data.i18n.en.actions!` / `actions_roll!`, `damage_type` предметов и заклинаний и
   `params.damage_type` узлов `action.damage` по существующему словарю типов урона.
3. **Спасброски заклинаний.** `tools/srd/fix_spell_saves.py` восстанавливает по официальному
   тексту `data.save_ability`, действие `kind=save` («СЛ {{@dc}} ЛОВ») и программу
   «Отдельный бросок: Спасбросок» — те же узлы, связи и тексты, что у 2014. Те же правила
   внесены в `tools/srd/build_srd.py`, поэтому пересборка даёт тот же результат (проверено:
   данные спасбросков совпадают у 318 из 318 заклинаний 2014 и 339 из 339 заклинаний 2024).
4. **Модуль повышения уровня.** `static/levelup.js` больше не держит своей таблицы навыков:
   ключ и название берутся из `window.SKILLS`, длинные id и «Анализ» остались только входными
   алиасами. Добавлен `LevelUp.canonicalSkills`, который приводит списки навыков листа к словарю.
5. **Миграция сохранений.** `static/sheet.js` при загрузке листа переводит навыки и
   экспертизу, сохранённые прежними версиями под длинными id, в канонические ключи
   (`animal_handling → animal`, `sleight_of_hand → sleight`). Повторы убираются, неизвестные
   значения остаются как есть — правки пользователя не теряются.
6. **Проверка целостности.** `tools/srd/integrity.cjs` дополнен: код возврата в режиме `--json`,
   проверка вынужденного спасброска по тексту, проверка «есть что бросать» для
   `data.actions_roll`, пустые обязательные поля различаются по источнику, формула урона
   допускает плоское значение.

Итог проверки: **0 ошибок, 12 предупреждений** (9 + 2 — намеренные совпадения слагов между
категориями: ключ БД — «категория/слаг»; 1 — слаг со скобками из индекса SRD 2024).

  создаются; при загрузке листа `static/sheet.js` переводит их в канонические ключи, не
  удаляя незнакомые значения. Регрессия проверяется тестом `LevelUp.canonicalSkills`.
* **Миграция справочника в развёрнутых базах**: `data_seed/previous_shipped.json` дополнен
  снимками прежних версий изменённых записей (2014: +445, стало 702 ключа; 2024: +522,
  стало 715). При запуске сервер обновит строки, которые совпали со снимком
  (`Upgrade::ReplaceShipped`), и не тронет правки пользователя — правило осталось прежним.
* **Формат данных не менялся**: новые спасброски записаны теми же полями и узлами, что у 2014
  (`save_ability`, `actions[].kind="save"`, программа `roll_only`), т. е. старые версии
  клиента и сервера читают записи без изменений.

## 11. Нерешённые проблемы

1. **Спасброски с несколькими характеристиками.** 6 заклинаний 2024 («Длань Аркан», «Радужные
   брызги», «Радужная стена», «Гроза мщения», «Символ», «Ледяная стена») и 4 заклинания 2014
   («Землетрясение», «Пир героев», «Радужная стена», «Символ») содержат разные спасброски для
   разных эффектов. В модели записи одна характеристика спасброска, поэтому данные не
   заполнены и остаются как **Не проверено**; это видно в отчёте
   `python3 tools/srd/fix_spell_saves.py --check`.
2. **Проверка «в тексте есть спасбросок»** остаётся эвристикой (русские формулировки) и даёт
   4 предупреждения для 2014 и 6 для 2024 — ровно перечисленные выше записи. Полностью
   машинно проверяемо только поле `dc` дампа 5.1.
3. **`data.actions_roll` у трёх монстров 2024** (`shrieker-fungus`, `vampire-mist`,
   `seahorse`) и четырёх 2014 (`frog`, `sea-horse`, `shrieker`, `vampire-mist`) отсутствует —
   по данным этих монстров бросать нечего (пустые действия или перемещение), проверка это
   учитывает, но полнота монстров по книге не сверялась.
4. **Слаг со скобками** `srd24-stone-of-good-luck-(luckstone)` приходит из индекса источника.
   Переименование затронуло бы ключи `legacy_hashes.json` / `previous_shipped.json` и ссылки в
   существующих базах, поэтому оставлено как есть (предупреждение проверки).
5. **Полный аудит правил не выполнен**: сверены машиночитаемые поля и терминология, но не
   каждая формулировка описаний, не классовые таблицы по книге, не экономика цен и веса
   всех предметов 2014 (в 2024 это проверено дампом), не все монстры (сопротивления,
   иммунитеты, тексты умений).
6. **Rust-тесты и smoke не запускаются в песочнице** (нет тулчейна, `static.rust-lang.org`
   недоступен) — проверка выполнена через CI GitHub. Это ограничение среды, а не пробел
   покрытия.
7. **`docs/mechanics-migration.json`** не пересобирался: файл отражает последний прогон
   `tools/srd/mechanics.py`, а новые программы спасброска добавлялись точечно
   (`tools/srd/fix_spell_saves.py`), чтобы не пересобирать механику всех 977/982 записей.
