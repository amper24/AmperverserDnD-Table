# Нодовая система v3

Цель: маленькие ортогональные блоки, условия у каждого блока, результаты действий,
доступные другим действиям, и понятная палитра без легаси. Обратной совместимости нет.

## Принципы

1. **Один блок — один глагол.** Блок либо вычисляет значение, либо меняет лист/предмет,
   либо управляет потоком. Составные узлы (adjust+condition+passive) сливаются в один
   `action.field` с параметром `kind`, как уже сделано для `rule.value/list/class`.
2. **Условие у каждого блока.** У всех блоков есть входы `enabled` (статическое условие:
   редакция/уровень/подкласс/выбор) и `condition` (динамическое bool-значение). Если
   условие ложно, блок пропускается, а поток идёт дальше по exec-выходу. Ветвление
   (`flow.if`) остаётся только для случаев, где нужны разные продолжения цепочки.
3. **Результаты принадлежат предмету/персонажу.** Выполнение действия пишет результат в
   состояние владельца: `sheet.results[<uid источника>][<program>] = { total, nat20, hit,
   applied, spent, at }`. Узел `data.result` читает последнее действие предмета или
   конкретную программу; `data.sheet` читает поле листа. Так одно действие может
   «посмотреть», что дало другое действие на этом же предмете, и использовать это в
   условиях и формулах.
4. **Рантайм-интерпретация.** Сервер исполняет граф по шагам (как клиентский предпросмотр),
   а не компилирует в статический план: только так работают динамические условия,
   результаты и выбор круга заклинания. `to_v1`/план удаляются.
5. **Палитра закрытая.** Незнакомый тип узла — ошибка; алиасов нет.

## Палитра v3

| Категория | Узлы |
|---|---|
| Поток | `action.program` (trigger: use/passive), `flow.if`, `flow.end` |
| Значения | `data.number`, `data.dice`, `data.stat`, `data.math`, `data.compare`, `logic.op`, `data.boolean`, `data.sheet`, `data.result` |
| Условия | `condition.context`, `condition.hit` |
| Действия | `action.roll`, `action.field`, `action.spend`, `action.grant_item`, `action.manual` |
| Правила | `rule.value`, `rule.list`, `rule.class`, `rule.manual` |
| Группы | `group.instance`, `group.input`, `group.output` |

Отдельных узлов изменения состояния, показателя и параметра при создании больше нет — их
заменяет один `action.field` с параметром `kind`; расход ресурса слит в `action.spend`;
сравнение чисел переехало в `data.compare`. `data.boolean` остаётся как константа.

### action.roll

Бросок с видом `roll_kind` (roll / attack / damage / heal / temp_hp), кубиками, DC и
режимом преимущества. Лечение и временные хиты применяются сразу; урон — это бросок,
результат которого применяет ДМ (или `action.field` по его решению).

### action.field

Изменение листа или состояния: `kind` = status / value / formula. `status` — имя
состояния в параметре `condition` и операция add/remove; `value` — поле листа `field`
и целое `amount`; `formula` — пассивный параметр при создании (`field`, `value`,
например формула защиты без доспехов). Урон, лечение и временные хиты — это броски
`action.roll`, а не `action.field`.

### action.spend

Расход ресурса: `resource` = quantity / charges / slot / uses, источник `source` =
self / item / tag, `amount` и момент `trigger` = use / attack. Расход ячейки
заклинания — `slot` с уровнем `slot_level` (1–9).

### data.result / data.sheet

`data.result` — `{ source: 'last' | <program_id>, field: 'total' | 'nat20' | 'hit' |
'applied' | 'spent' }`. `data.sheet` — путь поля листа (`hp.current`, `speed`, `gold`),
используется в условиях (`data.compare`) и формулах.

## Заклинания

Каст — программа с контекстом `slot_level`. Блоки: `action.spend` (slot), `action.roll`
(атака, урон или проверка), `data.compare` для спасброска против СЛ, `action.field` status
(концентрация), `action.manual` для ритуала.
Масштабирование: `data.math` с `slot_level` из контекста. Шаблоны заклинаний создают эти
цепочки автоматически; данные SRD пересобираются на них.

## Этапы

1. Палитра v3: слияние узлов, условия `enabled`/`condition` у блоков, миграция данных.
2. Рантайм-интерпретатор на сервере, состояние выполнения, `data.result`, `data.sheet`,
   сохранение результатов в листе, предпросмотр на клиенте.
3. Заклинания: круг, ячейка, upcast, концентрация, ритуал; пересборка заклинаний SRD.
4. Шаблоны: 15+ автоматических механик в диалоге шаблонов; документация и упрощение
   редактора (подсказки, пустые состояния, примеры).
