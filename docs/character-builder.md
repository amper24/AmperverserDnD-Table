# Мастер создания персонажа

`static/character-builder.js` подключён после `modules.js` и `compendium.js`
(страница приложения и страница листа персонажа — модель создания нужна редактору
справочника там же). Все три точки создания (личные персонажи, меню стола,
боковая панель) используют
`newCharacterDialog({ campaignId?, name? }) → Promise<{ name, sheet } | null>`.
Сохранение использует существующий `POST /api/characters`, миграция БД не нужна.

## Модули и расширение

Источником остаётся `/api/compendium`: SRD выбранной редакции, свои/подписанные
наборы и подключённые наборы/homebrew кампании. Создание модулей использует
существующий `Compendium.editEntry` с серверными проверками прав на набор.
Не создаётся отдельный каталог с несовместимыми данными.

Обработчики `CharacterBuilder.register(category, (sheet, entry) => …)` проецируют
данные модулей в новый лист. `CharacterBuilder.build(draft)` каждый раз начинает
с базовых характеристик; выбор другой расы не накапливает ASI. Подраса применяет
сначала родительскую запись (предпочтительно из того же источника).

В `sheet.modules[]` сохраняются:

- `schema_version: 1`;
- `entry_id`, `category`, `pack_id`, `source`;
- `snapshot`: независимая JSON-копия записи на момент создания.

Снимки можно посмотреть на листе во вкладке «Умения». Это история создания,
а не реактивная привязка: последующее изменение или удаление записи в справочнике
не меняет готового персонажа. `sheet.creation` содержит метод, базовые значения
характеристик и исходные броски (четыре кубика, индекс отброшенного, сумма).

Поддержаны существующие поля рас (`asi`, `speed`, `languages`, `traits`), классов
(`hit_die`, `saves`, `features`, `feature_texts`, `spellcasting`, `skills`),
предысторий (`skills`, `feature`, `feat`, `asi_options`) и преобразование заклинаний
через `Modules.spellFromCompendium`. Для новой категории нужны также разрешение
категории на сервере, редактор и шаг выбора — одной регистрации обработчика
недостаточно для добавления нового типа в интерфейс.

## Шаблоны блоков для новых расы, класса и предыстории

Новая запись этих категорий создаётся не пустой: `Mechanics.starter(category)`
подставляет схему `version: 1, origin: 'starter'`:

- **Параметры при создании** — пассивная программа: скорость 30 и бонус `asi.str +2`
  и язык у расы; кость хитов `d8`, спасбросок и выбор навыков у класса; навыки и
  языки у предыстории;
- **Умение** — программа по нажатию с одним ручным блоком (заготовка описания).

Шаблон не обязателен: блоки удаляются, меняются и дополняются как обычные.
В конструкторе для этих категорий рецепты соответствующие: «Бонус характеристики»,
«Навыки на выбор», «Умение (блоки)», «Владение». Владения, скорость и бонусы
характеристик приходят в лист через `Mechanics.passiveData`, а умения —
в `sheet.features`, поэтому изменение шаблона сразу меняет результат сборки.

## Выбор «либо / либо» (`data.choices`)

Раса, класс или предыстория может предложить игроку выбор. Группа описывается
в `data.choices` записи справочника:

```json
[{ "id": "lineage", "name": "Родословная", "type": "feature", "count": 1,
   "optional": false,
   "options": [
     { "id": "black", "name": "Чёрный дракон", "value": { "text": "Кислотное дыхание…" } },
     { "id": "blue",  "name": "Синий дракон",  "value": { "text": "Дыхание молнией…", "mechanics": { "version": 1, "programs": [] } } }
   ] }]
```

Тип группы определяет значение варианта:

| `type` | `value` варианта | Что делает на листе |
|---|---|---|
| `ability` | `{ "str": 2, "wis": 1 }` (целое −5…+5) | бонус к характеристикам |
| `skill` | `["stealth", "Скрытность"]` | владение навыками |
| `language` | `["Эльфийский"]` | языки во владениях |
| `feature` | `{ "text": "…", "mechanics": … }` | умение в `sheet.features` (с блоками) |
| `proficiency` | `"Военное оружие"` | строка во владениях |

`count` — сколько вариантов нужно выбрать (0…числа вариантов), `optional: true`
разрешает оставить выбор пустым. Ограничения: до 12 групп и до 18 вариантов
в группе, название до 120 символов, описание умения до 4 000.

Мастер показывает группы на шаге **«Происхождение»** под карточками модулей
(один вариант — переключатель, несколько — флажки) и не пропускает дальше,
пока выбор не сделан. Смена модуля сбрасывает чужие отметки. `build(draft)`
применяет выбранные варианты один раз — как и остальные проекции — и пишет
итог в `sheet.creation.choices` (`group`, `name`, `type`, `source`).
Пустой выбор ничего не даёт: это решение игрока, а не значение по умолчанию.

Схему проверяют `CharacterBuilder.validateChoices` (в редакторе и перед
сохранением) и `mechanics::validate_choices` на сервере при создании и
изменении записи. Группы видны в карточке модуля и в описании мастера.

## Границы автоматизации

Мастер создаёт персонажа первого уровня. Бонусы 2014 берутся из расы; 2024 —
распределяются пользователем из `asi_options` предыстории. Хиты рассчитаны как
максимум кости класса + модификатор Телосложения (минимум 1); КД — 10 + Ловкость.
Текстовые особенности (например, дополнительный хит дварфа, защита без доспехов),
варианты владений, черт и стартового снаряжения не интерпретируются как код.
Снаряжение с вариантами сохраняется в заметках, а не выдаётся целиком.

Заклинания выбираются свободно среди заговоров и первого круга: лимиты известных,
принадлежность классу, подготовка и ячейки пока настраиваются на листе. Эти ограничения
явно показаны в мастере. Это расширяемая основа, а не полный валидатор правил D&D.

## Проверка

Без дополнительных зависимостей:

```sh
node --test tests/character-builder.test.cjs
node --test tests/mechanics.test.cjs
node --check static/character-builder.js
node --check static/mechanics.js
```

Тесты покрывают 4d6, повторную сборку без накопления бонусов, смену расы, редакции,
подрасы, независимые снимки, расширение реестра, стартовые шаблоны блоков,
проверку схемы выбора и применение выбранных вариантов (характеристики, навыки,
языки, владения, умения).
