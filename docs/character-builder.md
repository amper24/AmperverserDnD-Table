# Мастер создания персонажа

Правила создания живут в `static/character-builder.js` (модуль
`CharacterBuilder`: проекции записей справочника, выборы «либо/либо», разбор
стартового снаряжения, сборка листа), а окно мастера из восьми шагов —
в `static/builder-dialog.js` (`newCharacterDialog`). Оба файла подключены после
`modules.js` и `compendium.js` (страница приложения и страница листа персонажа —
модуль нужен редактору справочника там же; само окно используется только
в `index.html`). Все три точки создания (личные персонажи, меню стола,
боковая панель) используют
`newCharacterDialog({ campaignId?, name? }) → Promise<{ name, sheet } | null>`.
Сохранение использует существующий `POST /api/characters`, миграция БД не нужна.

## Все шаги необязательны

Мастер ничего не требует: кнопка «Далее →» и переход по любому шагу в навигации
работают всегда, а незаполненное остаётся отмеченным подсказкой («! … — можно
пропустить») в шаге и в навигации. Итоговый лист собирается из того, что выбрано:
пропущенные раса, класс, предыстория, навыки, языки, заклинания или снаряжение
просто остаются пустыми, и их можно заполнить уже на странице листа. Пустое имя
заменяется на «Новый персонаж».

Проверки шагов (`stepProblem(i)` в `builder-dialog.js`) остаются подсказками о
правилах — они считают, что по книге ещё нужно выбрать, но не запрещают переход
и не блокируют создание. Когда на шаге есть такая подсказка, рядом с «Далее →»
появляется явная кнопка «Пропустить шаг».

Отдельный выход — кнопка **«Заполнить самостоятельно»** внизу окна мастера
(доступна на любом шаге). Она закрывает мастер и создаёт пустой лист 1 уровня:
без расы, класса, предыстории, снаряжения и умений, с нейтральными характеристиками
10 и хитами от `d8`; имя и редакция берутся из уже введённого. Такой лист помечен
`sheet.creation.manual = true`, а всё остальное игрок заполняет на листе сам.

## Модули и расширение

Источником остаётся `/api/compendium`: SRD выбранной редакции, свои/подписанные
наборы и подключённые наборы/homebrew кампании. Создание модулей использует
существующий `Compendium.editEntry` с серверными проверками прав на набор.
Не создаётся отдельный каталог с несовместимыми данными.

Обработчики `CharacterBuilder.register(category, (sheet, entry) => …)` проецируют
данные модулей в новый лист. `CharacterBuilder.build(draft)` каждый раз начинает
с базовых характеристик; выбор другой расы не накапливает ASI. Подраса применяет
сначала родительскую запись (предпочтительно из того же источника).

В `sheet.modules[]` сохраняются:

- `schema_version: 1`;
- `entry_id`, `category`, `pack_id`, `source`;
- `snapshot`: независимая JSON-копия записи на момент создания.

Снимки можно посмотреть на листе во вкладке «Умения». Это история создания,
а не реактивная привязка: последующее изменение или удаление записи в справочнике
не меняет готового персонажа. `sheet.creation` содержит метод, базовые значения
характеристик и исходные броски (четыре кубика, индекс отброшенного, сумма).

Поддержаны существующие поля рас (`asi`, `speed`, `languages`, `traits`), классов
(`hit_die`, `saves`, `features`, `feature_texts`, `spellcasting`, `skills`),
предысторий (`skills`, `feature`, `feat`, `asi_options`) и преобразование заклинаний
через `Modules.spellFromCompendium`. Для новой категории нужны также разрешение
категории на сервере, редактор и шаг выбора — одной регистрации обработчика
недостаточно для добавления нового типа в интерфейс.

## Шаблоны блоков для новых расы, класса и предыстории

Новая запись этих категорий создаётся не пустой: `Mechanics.starter(category)`
подставляет схему `version: 1, origin: 'starter'`:

- **Параметры при создании** — пассивная программа: скорость 30 и бонус `asi.str +2`
  и язык у расы; кость хитов `d8`, спасбросок и выбор навыков у класса; навыки и
  языки у предыстории;
- **Умение** — программа по нажатию с одним ручным блоком (заготовка описания).

Шаблон не обязателен: блоки удаляются, меняются и дополняются как обычные.
В конструкторе для этих категорий рецепты соответствующие: «Бонус характеристики»,
«Навыки на выбор», «Умение (блоки)», «Владение». Владения, скорость и бонусы
характеристик приходят в лист через `Mechanics.passiveData`, а умения —
в `sheet.features`, поэтому изменение шаблона сразу меняет результат сборки.

## Выбор «либо / либо» (`data.choices`)

Раса, класс или предыстория может предложить игроку выбор. Группа описывается
в `data.choices` записи справочника:

```json
[{ "id": "lineage", "name": "Родословная", "type": "feature", "count": 1,
   "optional": false,
   "options": [
     { "id": "black", "name": "Чёрный дракон", "value": { "text": "Кислотное дыхание…" } },
     { "id": "blue",  "name": "Синий дракон",  "value": { "text": "Дыхание молнией…", "mechanics": { "version": 1, "programs": [] } } }
   ] }]
```

Тип группы определяет значение варианта:

| `type` | `value` варианта | Что делает на листе |
|---|---|---|
| `ability` | `{ "str": 2, "wis": 1 }` (целое −5…+5) | бонус к характеристикам |
| `skill` | `["stealth", "Скрытность"]` | владение навыками |
| `language` | `["Эльфийский"]` | языки во владениях |
| `feature` | `{ "text": "…", "mechanics": … }` | умение в `sheet.features` (с блоками) |
| `proficiency` | `"Военное оружие"` | строка во владениях |

`count` — сколько вариантов нужно выбрать (0…числа вариантов), `optional: true`
разрешает оставить выбор пустым. Ограничения: до 12 групп и до 18 вариантов
в группе, название до 120 символов, описание умения до 4 000.

Мастер показывает группы на шаге **«Происхождение»** под карточками модулей
(один вариант — переключатель, несколько — флажки) и показывает подсказку, пока
выбор не сделан; пройти дальше можно и без выбора — тогда вариант не применяется.
Смена модуля сбрасывает чужие отметки. `build(draft)`
применяет выбранные варианты один раз — как и остальные проекции — и пишет
итог в `sheet.creation.choices` (`group`, `name`, `type`, `source`).
Пустой выбор ничего не даёт: это решение игрока, а не значение по умолчанию.

Схему проверяют `CharacterBuilder.validateChoices` (в редакторе и перед
сохранением) и `mechanics::validate_choices` на сервере при создании и
изменении записи. Группы видны в карточке модуля и в описании мастера.

## Навыки и языки (шаг «Навыки»)

Пул навыков собирается из трёх источников: выбор класса (`data.skills` записи или
пассивной программы — `count` и список), навыки предыстории и навыки, уже выданные
выбором модуля («либо/либо» или раса/предыстория). Уже полученные навыки показаны
отдельными метками с источником («предыстория · Прислужник») и в пуле не отмечаются — повторно их взять нельзя.
Каждая плитка показывает модификатор характеристики и итоговое владение (`+2 мод`, `владение +4`), а счётчик
«X из N · ещё K» относится только к выбору класса: счётчик показывает, сколько осталось
отметить, но шаг можно пропустить и без полного выбора.
Если класс ещё не даёт навыков, панель так и говорит, а не блокирует шаг. Результат пишется в `sheet.skills`.

**Взаимозамена.** Если навык из списка класса уже выдан расой, предысторией или выбранным вариантом модуля,
он не отмечается в списке класса: панель «Взаимозамена навыков» предлагает взять вместо него любое другое
владение (по правилам владение из двух источников не складывается). В панели видно, какие навыки совпали и с каким
источником, счётчик «X из N · ещё K» считается по числу совпадений; замены тоже можно
не выбирать — шаг это не блокирует.
Выбранные замены лежат в `draft.freeSkills`, попадают в `sheet.skills` и сбрасываются при смене класса,
предыстории или редакции.

Языки выбираются в панели «Дополнительные языки». Для редакции 2024 Общий добавляется
автоматически, а два дополнительных языка выбираются только из стандартного списка
(включая Общий жестовый); плут получает ещё один выбор языка. Для редакции 2014
панель считает языки от предыстории и особенности расы; известные расовые языки
показываются и не предлагаются повторно. Языки класса Друида и Плута добавляются
как владения по классовой особенности. Итог попадает в `sheet.proficiencies`.
Классовые выборы первого уровня представлены отдельными панелями: три музыкальных
инструмента барда в обеих редакциях, боевой стиль воина 2014, божественный/первобытный
орден 2024, мастерство оружия 2024 и экспертиза плута; выбранные значения сохраняются
в листе или проецируются в умения.

## Стартовое снаряжение (шаг «Снаряжение»)

Снаряжение выдаётся не текстом в заметках, а предметами в `sheet.inventory` —
с UID, количеством, слотами и хватом (`docs/inventory.md`). Разбор текста
класса и предыстории живёт в `static/character-builder.js`:

- `parseEquipmentText(text, source)` → блоки `fixed` (выдаётся всегда) и `group`
  (выбор одного варианта). Поддержаны форматы 2014 («- (a) X или (b) Y»,
  «Название ×N») и 2024 («Выберите А или Б: (А) …; или (Б) 75 зм»);
- `parseItemToken` разбирает элемент на `item` / `gold` / `pick`: количество
  берётся из ×N, из цифры в скобках у считаемых единиц («Факел (10)») или из
  слова «два/2»; «15 зм» — золото; «колчан с 20 стрелами» разворачивается в
  колчан и стрелы; «выбранные выше» (2024) — пустой список, потому что предмет
  уже учтён;
- `equipmentPlan(draft)` собирает блоки выбранных класса и предыстории,
  `equipmentItems(draft)` — конкретные предметы и золото. Ключ строки
  `<блок>:<вариант|->:iN|pN[:слот]` хранится в `draft.equipment`; стандартный режим
  выдаёт выбранный по правилам состав, а исключения, изменение количества,
  шаблонов/названий и добавление вещей/золота применяются только при явном
  включении `gmOverrides` («Ручные правки мастера»).
- `pickEntry` принимает только явный выбор игрока (`draft.equipment.picks`) из
  подходящей категории `PICK_FILTERS` (тип оружия, инструменты, священный символ,
  магическая/друидическая фокусировка, набор); текстовое предпочтение показывается
  как подсказка, но не выбирается за игрока. Неподходящий ID отклоняется, пустой
  фильтр/слот блокирует переход, а не подставляет первую запись;
- наборы («Набор путешественника») — запись справочника с описанием «Содержимое: …»:
  строка-контейнер плюс дочерние предметы с `parent`, количеством `qty × qty набора`
  и отдельными UID; выключатель «Раскладывать наборы на содержимое» (`packs`)
  оставляет набор одной строкой;
- имена сопоставляются с записями справочника по нормализованному названию и
  основам слов («Коротких меча» → «Короткий меч», «20 болтов» → «Арбалетный
  болт», «деревянный щит» → «Щит»). Если шаблона нет (например, 2024 «Ряса»),
  предмет всё равно создаётся по названию, а `entry` остаётся пустым;
- выключатель «Надеть доспех, щит и основное оружие сразу» (`autoEquip`) надевает
  доспех на тело, щит — во вторую руку, одноручное — в основную; двуручное —
  только если обе руки свободны.

Итог шага — `sheet.creation.equipment = { gold, items }`, а сами предметы
собираются тем же кодом, что и на листе: `Modules.itemFromCompendium` либо
`newItem`, затем `Equipment.normalize`. Поэтому количества, стопки, расход,
слоты и хват работают сразу, а не после ручной правки.

## Проверки правил и границы автоматизации

Мастер создаёт персонажа 1 уровня по выбранной редакции. Для характеристик доступны
стандартный набор, бросок `4d6` с отбрасыванием меньшего, покупка очков по таблице D&D
(ровно 27 очков, значения 8–15) и ручной ввод значений 1–20. Также доступен отдельный
бросок `6 × 1d20`; полученные результаты можно распределить между характеристиками
перестановкой значений. `6d20` — вариант по договорённости за столом, а не стандартный
способ создания из правил. Бонусы расы и предыстории применяются отдельно. Произвольные
предметы, удаление вещей, изменение количества и дополнительное золото скрыты за явно
включаемым режимом мастера и не применяются в стандартном создании. Бонусы 2014
берутся из расы, 2024 распределяются по `asi_options` предыстории как `+2/+1` или
`+1/+1/+1`. Для стандартного набора, покупки очков и `4d6` проверяется итоговый диапазон 3–20; ручной ввод и вариант `6d20` допускают диапазон 1–20. Хиты — максимум кости
класса + модификатор Телосложения (минимум 1). Стартовые навыки, владения, выборы модулей,
предметы и конфликты экипировки собираются из записей справочника. Каждый вариант стартового снаряжения и каждый слот «выберите предмет» нужно подтвердить выбором: без него предмет в инвентарь не попадает (шаг при этом не блокируется, а слот остаётся пустым). Неподходящий предмет нельзя подставить в слот.

Класс и предыстория выбираются как записи справочника и сохраняются снимками в `sheet.modules`.
Подкласс — вложенная запись внутри выбранного класса: если первое умение подкласса даётся
на 1 уровне, его нужно выбрать здесь; умения и снимок подкласса попадают в лист отдельно.
Если класс получает подкласс позже, выбор появляется в мастере повышения уровня на нужном
уровне. Повышение использует таблицы развития обеих редакций, ограничение общего уровня 20,
проверку мультиклассовых требований, соответствующие умения, хиты, ASI/черты, подклассы,
известные заклинания и ячейки; отмена последнего повышения восстанавливает затронутые поля. Выборы навыков уровня 1 сверяются со списками всех 12 классов обеих редакций; при повышении запрашиваются дополнительные навыки Коллегии знаний и выборы варианта подкласса, если варианты явно записаны в справочнике. Дополнительный заговор Круга Земли 2014 и бонус характеристики от черты также учитываются. Ручное значение хитов ограничено размером кости, а повышение выше 20-го уровня блокируется.

На создании заклинания фильтруются по классу и уровню; количество заговоров, известных/
подготовленных заклинаний или стартовых записей в книге берётся из таблицы класса для
выбранной редакции. Ячейки первого уровня создаются сразу. У волшебника выбираются шесть
заклинаний в книгу и отдельно обязательное число подготовленных заклинаний по модификатору
Интеллекта. Всегда подготовленные заклинания Друида 2024, Следопыта 2024 и домена Жизни
Жреца 2014 добавляются сверх обычного лимита. Заклинание без указания классового списка не предлагается как доступное классу; не-колдующие классы и homebrew-классы без таблицы не получают произвольный список заклинаний.

Вложенные выборы «Посвящённого в магию» поддержаны отдельно, в том числе когда эту черту выбирает человек 2024 как дополнительную черту происхождения. Для обычной черты нужно выбрать список Жреца/Друида/Волшебника; пометка «(Жрец)» в предыстории фиксирует список Жреца. Мастер требует также выбрать заклинательную характеристику, два разных заговора и одно заклинание 1-го уровня из того же списка; все три заклинания добавляются в лист с характеристикой черты, вне классового лимита; характеристика сохраняется у каждого заклинания и применяется при бросках на листе и в карточках чата. Использование заклинания 1-го уровня без ячейки (один раз до продолжительного отдыха по тексту черты) остаётся описанным умением: отдельный счётчик использований лист пока не ведёт. Автоматически рассчитываются КД защиты без доспехов варвара и монаха с ограничением щита для монаха; владения оружием дварфа и эльфа 2014 и расовые заговоры проецируются отдельно. Остальные текстовые особенности без механических блоков не обязательно автоматизированы. Изменения стартового снаряжения доступны только как явные правки мастера; стандартная выдача использует выборы класса и предыстории. Также не проверяются ограничения сеттинга/расы и исключения, не описанные в записях. Это не универсальный валидатор произвольного homebrew — спорные и неструктурированные правила нужно сверить с выбранной книгой/редакцией.

## Проверка

Без дополнительных зависимостей:

```sh
node --test tests/character-builder.test.cjs
node --test tests/character-builder-equipment.test.cjs
node --test tests/character-builder-dialog.test.cjs
node --test tests/mechanics.test.cjs
node --check static/character-builder.js
node --check static/builder-dialog.js
node --check static/mechanics.js
```

`character-builder-dialog.test.cjs` открывает мастер в песочнице с настоящим
справочником SRD 2014 и проходит все восемь шагов до готового листа: модули,
подкласс и инструменты дварфа, покупка очков, навыки с взаимозаменой, языки,
варианты снаряжения и выбор священного символа. Два других теста проверяют
необязательность: мастер пускает вперёд семь раз подряд без единого выбора и всё
равно создаёт лист (с именем по умолчанию), а кнопка «Заполнить самостоятельно»
возвращает пустой лист 1 уровня с нейтральными характеристиками.

Тесты покрывают броски 4d6 и 6d20, повторную сборку без накопления бонусов, смену расы, редакции,
подрасы, независимые снимки, расширение реестра, стартовые шаблоны блоков,
проверку схемы выбора и применение выбранных вариантов (характеристики, навыки,
языки, владения, умения).

`character-builder-equipment.test.cjs` проверяет разбор стартового снаряжения на
записях реального SRD обеих редакций для всех 12 классов: блоки и варианты,
количества и боеприпасы, сопоставление названий, подстановку по фильтрам,
шаблоны/слоты/КД, щит и двуручное оружие, золото и исключения, наборы целиком и
разложенные, а также чистоту повторной сборки (UID не переиспользуются).

## Переход правил персонажа на v2

Новый редактор графа механик подключён к редактору записи; его правила можно предварительно просматривать для SRD 2014/2024 и уровня 1–20 без сохранения. `rule.*` — общие узлы проекции; `condition.*`/`flow.if` управляют значениями по редакции, уровню, подклассу и выборам. Совместимость с `data.mechanics` v1 и `data.choices` сохраняется.

**Статус:** исполнитель rule-графа подключён к сборке персонажа, но SRD ещё не перенесён на графы; существующие правила мастера остаются источником для действующей сборки до завершения поэтапной миграции. Нельзя считать эту промежуточную версию достаточной для отключения старых обработчиков.
