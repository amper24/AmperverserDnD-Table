# Архитектура фронтенда

Фронтенд собирается **без бандлера**: обычные скрипты подключаются тегами
`<script>` в строгом порядке (см. комментарии-слои в `static/index.html`
и `static/sheet.html`). Файлы общаются только через глобальные объекты
`window.*`; прямых импортов нет, поэтому порядок загрузки — часть контракта.

## Слои

| Слой | Что это | Файлы |
|---|---|---|
| 1. Фундамент | хранилище с согласием на cookie, API-клиент, DOM-помощники (`el`, `modal`, `floatWindow`, `toast`, `icon`), словари (`SKILLS`, `ABIL`, `EDITIONS`, `CAT_NAMES`), тема; права UI (`Access.can`) — зеркало `src/access.rs`; единая навигация (пункты, активный раздел, шапка) | `common.js`, `access.js`, `nav.js` |
| 2. Движки правил | физика и визуализация принятых бросков, движок кубиков и журнал; слоты экипировки (зеркало `src/inventory.rs`); декларативные механики умений; учёт ячеек заклинаний | `dice-physics.js`, `dice-visual.js`, `dice.js`, `equipment.js`, `mechanics.js`, `spell-rules.js` (только лист) |
| 3. Данные | модель записей листа (предмет/заклинание/умение, карточки, чат, редакторы); справочник (поиск, редактор записи, перетаскивание); таблицы развития классов — **сгенерированные данные**, не править вручную | `modules.js`, `compendium.js`, `class-progression.js` |
| 4. Создание персонажа | правилное ядро (`CharacterBuilder`: проекции модулей, выборы «либо/либо», разбор снаряжения, сборка листа) и мастер-окно из восьми шагов (`newCharacterDialog`) — отдельно правила, отдельно UI | `character-builder.js`, `builder-dialog.js` |
| 5. Возможности | мастерская наборов; импорт из Long Story Short; canvas-стол; повышение уровня | `packs.js`, `lss.js`, `table.js` (index), `levelup.js` (sheet) |
| 6. Страницы | лобби и кампания/стол; лист персонажа | `app.js` (index.html), `sheet.js` (sheet.html) |

Правило зависимостей: слой ссылается только на более ранние слои. Если нижнему
слою нужен верхний (например, `modules.js` использует редактор выборов
`CharacterBuilder`), обращение делается **лениво** — при вызове обработчика или
через `window.X?.`, а не при загрузке файла.

Отдельные страницы: `index.html` (лобби и стол), `sheet.html` (лист
персонажа, также встраивается в стол через iframe с `embed=1`), `table.html`
(участники кампании; лёгкий набор скриптов, см. `docs/table.md`), `profile.html`
(профиль). Все они подключают `nav.js`/`nav.css` после `common.js`/`style.css`.
Мастер создания нужен только страницам со списком персонажей, поэтому
`builder-dialog.js` подключён лишь в `index.html`; листу достаточно правил
`CharacterBuilder` (словари и редактор выборов в справочнике).

## Создание персонажа: правила отдельно от окна

`CharacterBuilder` — чистая проекция `draft → sheet`: любая правка черновика
пересобирает лист с нуля, бонусы не накапливаются. Модуль не знает про DOM
за пределами редактора выборов. Всё окно (шаги, валидация переходов, карточки
модулей, снаряжение, итоговая проверка) живёт в `builder-dialog.js` и вызывает
модуль через `B = CharacterBuilder`. Точки входа: «Новый персонаж» в лобби,
меню «Создать» на столе и боковая панель кампании.

Уровень-в-уровень похожие помощники есть и в `levelup.js`
(`subclassLevel`, `subclassVariantGroups`): повышение уровня намеренно
независимо от создания персонажа и работает с уже готовым листом, поэтому
дублирование осознанное.

## Шапка и футер листа

Верхняя строка `sheet.js`/`topBar` намеренно короткая: имя, статус, «В окно»
(в embed), «Справочник», «Переменные…», «Обновить» и «виден игрокам». Кнопки
темы и селектора редакции там нет — они уехали в футер (`sheetFooter`): слева
селектор редакции (прежнее поведение — `save()` и перерисовка), справа
маленькая кнопка темы. Портрет — единственная точка входа для портрета и токена: клик
или Enter/Space открывает меню «Загрузить файл / Из библиотеки / Убрать» и
«Выбрать токен…»; удаление и выбор ассета по-прежнему идут через
`PATCH /api/characters/:id { portrait_asset_id }`, токен — через
`M.imagePicker` и `token_asset_id`.

Блоки шапки — снимки модулей: раса, класс и предыстория меняются только
перетаскиванием записи из справочника (у блока есть `data-cat`), подкласс —
мастером повышения уровня. Инлайн-правки `ui.headEdit`/`editInput` удалены,
поэтому клик по классу, подклассу и предыстории ничего не открывает.
Мировоззрение — кастомный дропдаун (`align-picker`, роль `listbox`) с теми же
`ALIGNMENTS`, пустое значение подписано «Не указано», значение пишется в
`s.alignment` и сохраняется через `save()`.

Все всплывающие панели листа (`attachPopover`) живут по одному правилу:
одновременно открыта максимум одна, открытие закрывает прежнюю, а закрытие
происходит по Esc, клику вне, скроллу, `resize` и перед `render()`. Закрытая
панель получает `hidden` и `display:none !important` из `sheet-polish.css`,
поэтому не остаётся прозрачным слоем над инвентарём; декоративные подписи
блоков имеют `pointer-events:none`.

## Переменные листа

Числа, которые действия с узлом `action.setvar` (`scope: sheet`) кладут в
`sheet.vars`, видны и правятся в диалоге «Переменные…» из шапки листа
(`sheet.js`, `openVarsDialog`). Имя и значение проверяют общие функции
`SheetVars` (`sheet-vars.js`): имя — 1–32 символа `[a-z0-9_]` и только
уникальное, значение — конечное число (запятая как десятичный разделитель).
Диалог меняет `s.vars` и вызывает обычный `save()`, поэтому отдельного
эндпоинта и хранилища нет; `normalizeSheet` при загрузке отбрасывает мусор.
В readonly-листе доступен только просмотр. Удаление всех значений требует
второго клика по «Точно?» внутри диалога.

## Навигация

Шапку рисует один общий модуль — `static/nav.js` (+ `static/nav.css`). Он
подключён после `common.js` в `index.html`, `sheet.html`, `table.html` и
`profile.html`, поэтому на всех страницах одинаковые пункты и одинаковое
поведение. Состав и порядок пунктов — единственная точка правды `Nav.ITEMS`:

| Пункт | key | href | Активен на |
|---|---|---|---|
| Главная (логотип) | `home` | `/` | `/` |
| Кампании | `campaigns` | `/campaigns` | `/campaigns`, `/c/…` |
| Персонажи | `characters` | `/characters` | `/characters`, `/sheet/…`, `/character/…` |
| Справочник | `compendium` | `/compendium` | `/compendium` |
| Стол | `table` | `/c/<cid>` или `/campaigns` | `/table/…` |
| Профиль | `profile` | `/profile` | `/profile` |

- `Nav.activeKey(pathname)` — единственное место, где путь превращается в
  активный пункт; `Nav.build(links, pathname)` — чистая функция (копии пунктов
  с флагом `active`), её проверяет `tests/nav.test.cjs`. Активный пункт получает
  `aria-current="page"`; логотип подсвечивается на главной.
- `Nav.items(pathname)` подставляет адрес «Стола»: со страницы участников
  (`/table/:cid`) и со стола (`/c/:cid`) — стол этой же кампании, иначе
  последняя открытая кампания (`et-last-campaign`; её пишет `app.js` при
  открытии стола), иначе список кампаний. Без истории пункт не ломается.
  Ключ функциональный: без согласия на cookie он живёт только в памяти, и
  «Стол» ведёт в список кампаний (см. «Cookie и хранилище» в `renderPrivacy`).
- `Nav.header({ me, current, active, theme, logout, admin, canRegister })` —
  полная шапка: логотип, пункты, бургер, «Админ» для root, тема, пользователь и
  «Выйти». `active` нужен только страницам вне карты путей (`/admin`).
  `Nav.menu({ current })` — компактное меню «Разделы» для плотной панели
  полноэкранного стола (`.tbar` в `app.js`), с тем же списком и подсветкой.
- Роутинг не трогается: пункты — обычные `<a href>`, `history`/`pushState`
  не используются, поэтому SPA (`app.js`) продолжает работать как раньше, а
  `/profile`, `/table/:cid` и `/sheet/:id` открываются полной навигацией.
  На полноэкранном столе широкой шапки нет — только меню «Разделы»; лист в
  `embed=1` (поверх стола) шапку не рисует, чтобы не занимать место.
- Узкий экран (≤ 800px): широкий список скрыт, вместо него бургер с
  выпадающим меню (`aria-expanded`/`aria-controls`, Esc и клик вне закрывают).
  Стили берут цвета и радиусы из переменных `style.css`, поэтому тёмная и
  светлая темы работают без отдельных правил; `:focus-visible` даёт видимую
  рамку, переходы отключаются при `prefers-reduced-motion`.
- Дубли локальных ссылок убраны: в шапках `table-page.js` и `profile-page.js`
  больше нет своих «Кампании/Персонажи/Справочник», у листа таких ссылок не
  было; осталась только общая шапка. Кнопка «Справочник» в верхней строке
  листа — не ссылка на раздел, а встроенный справочник для перетаскивания,
  поэтому она сохранена.

## Главная

`renderHome` в `app.js` — панель пользователя: приветствие, быстрые действия
(«Новая кампания», «Новый персонаж», «Присоединиться по коду»), «Мои кампании»,
«Мои персонажи» и прежние карточки разделов (`sectionCards`), чтобы остались
доступны библиотека и наборы.

- Данные — существующие API: `GET /api/campaigns` и `GET /api/characters`
  запускаются параллельно (`Promise.allSettled`), затем для показанных
  кампаний (до шести) параллельно запрашиваются детали (`GET /api/campaigns/:id`
  — число участников) и сцены (`GET /api/campaigns/:id/scenes` — активная или
  последняя сцена). Новых серверных эндпоинтов нет.
- Карточка кампании: название, роль (`мастер`/`игрок`), число участников,
  сцена, кнопки «Открыть» (`/c/:id`), «На стол» (та же ссылка в новой вкладке) и
  «Участники» (`/table/:id`). Карточка персонажа: имя, уровень, раса/класс/
  подкласс, кампания (из общего списка кампаний) и «Лист» (`/sheet/:id` в новой
  вкладке, как раньше).
- Пока данные грузятся, в секциях стоят скелетоны (`aria-busy`); пустые списки
  показывают подсказку и кнопку действия (создать кампанию/персонажа,
  присоединиться по коду); ошибка загрузки — карточка с «Повторить». Скелетоны
  не анимируются при `prefers-reduced-motion`.
- Прежние возможности сохранены: создание кампании (`prompt2` +
  `POST /api/campaigns`), создание персонажа (`newCharacterDialog` +
  `POST /api/characters`), присоединение по коду или ссылке (`/join/:code`).

## Конвенции кода

- Заголовок файла: одна строка «что это», затем «Даёт: …», «Зависимости: …»,
  где загружается. Внутри файла секции отмечаются
  `// ---------- раздел ----------`, документация функций — `///`.
- Состояние страницы держится в замыкании её скрипта; наружу отдаются только
  переиспользуемые модули (`window.*`).
- Все данные с сервера идут через `API.*`; ошибки показываются `toast`.
- Тексты интерфейса — русские; названия полей данных — английские.

## Проверка

Юнит-тесты фронтенда исполняют скрипты в `node:vm` со стабами браузера
и настоящими данными `data_seed/`, без внешних зависимостей:

```sh
node --test tests/*.test.cjs
```

Браузерные сценарии — отдельные `tests/*.browser.cjs` (Playwright), запускаются
точечно: `node tests/sheet.browser.cjs` проверяет шапку и футер листа, меню
портрета, нередактируемые класс/подкласс/предысторию, дропдаун мировоззрения
и то, что попап не перехватывает клик по инвентарю. `node tests/nav.browser.cjs`
проверяет единую навигацию на index/sheet/table/profile (одинаковые пункты,
активный раздел по адресу, переход по пункту, отсутствие дублей), бургер на
узком экране и содержимое главной: карточки кампаний и персонажей, быстрые
действия и присоединение по коду.

Ключевые наборы: `character-builder.test.cjs` (проекция и сборки),
`character-builder-equipment.test.cjs` (разбор снаряжения на реальном SRD),
`character-builder-dialog.test.cjs` (мастер открывается, доходит до готового
листа, пропускает незаполненные шаги и собирает пустой лист), `levelup.test.cjs`, `mechanics.test.cjs`, `equipment.test.cjs`,
`dice.test.cjs`, `dice-physics.test.cjs`, `dice-visual.test.cjs`, `spell-rules.test.cjs`.
