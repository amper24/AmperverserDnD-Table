# Редактор расы

Отдельный конструктор расы по образу редактора класса: **Справочник → Расы →
«+ Создать свою запись»** или **«Редактировать» в карточке расы**. Код —
`static/race-editor.js` (`window.RaceEditor`), стили — те же `.ced-*`, что у
редактора класса (`static/style.css`).

Правится на отдельной странице со своим адресом (`/race-editor/<id>` и `/background-editor/<id>`): тот же экран, что у редактора класса, — разделы редактора, выбор места хранения для новой записи и сохранение в саму запись справочника (`static/editor-page.js`, `window.EditorPage`). Модалка осталась запасным путём для встраиваемых мест (стол, лист персонажа).

## Разделы

| Раздел | Что правится |
|---|---|
| **Общее** | название (ru/en), редакция, размер, скорость, родительская раса (для разновидности), описание, возраст, рост и вес |
| **Характеристики** | фиксированные бонусы (+2, +1 …) по шести характеристикам |
| **Языки** | языки расы списком + отдельное примечание («Вы можете говорить, читать и писать на…») |
| **Заклинания** | заговоры и заклинания расы: известные сразу (перетащите запись «Заклинания» из справочника) и выбор игрока — сколько, какого круга, из списка каких классов, с какой характеристикой |
| **Навыки** | владение навыками (можно перетащить запись «Навыки» из справочника) и выбор игрока: сколько и из каких |
| **Владения** | владения по видам: доспехи, оружие, инструменты, своё |
| **Черты** | особенности расы: название и текст (кнопки бросков в тексте работают на листе) |
| **Подрасы** | список разновидностей (сами разновидности — отдельные записи с родительской расой) |

## Правила расы — узлы графа

Мастер создания персонажа читает правила расы из графа (`rule.*`), поэтому
редактор правит **и узлы, и сырые поля записи**:

| Что | Узел | Поле записи |
|---|---|---|
| скорость | `rule.speed` | `data.speed` |
| языки | `rule.languages` | `data.languages` (имена + примечание) |
| бонусы характеристик | `rule.ability_bonus` (по узлу на характеристику) | `data.asi` |
| владение навыком | `rule.skill_proficiency` | `data.skills` |
| выбор навыков игроком | `rule.skills` (id, count, options) | — |
| владения | `rule.proficiencies` (по узлу на вид) | — |
| заклинания, известные сразу | `rule.spell_list` (mode `known`, список названий, характеристика) | `data.cantrips` |
| выбор заклинания игроком | — | `data.spell_choices` |
| заклинательная характеристика | — | `data.spell_ability_choice` |
| черты | `action.program` (`group: 'traits'`) + `action.manual` | `data.traits` |

Узлы обновляются **на месте**: сохраняются их id и связи (например, условие
редакции `condition.edition` у бонуса характеристики). Пассивные блоки старого
формата (`action.passive` со скоростью, языками, `asi.*` и навыками)
синхронизируются вместе с узлами, иначе лист показал бы прежние значения.
Черта, переименованная в редакторе, сохраняет свою программу графа; удалённая
черта уносит программу и её текстовый узел.

Неизвестные редактору поля и прочие узлы записи (пассивные программы, условия,
свои группы) сохраняются как есть.

## Навыки и графы

Запись навыка (категория «Навыки») несёт свой граф с узлом
**`rule.skill_proficiency`** — тем же, что пишет редактор расы. Поэтому:

- навык, перетащенный в раздел «Навыки», попадает в узел `rule.skill_proficiency`;
- навык, перетащенный на лист персонажа, раздаёт владение через проекцию графа
  (`Mechanics.applyGraphRules`), а не отдельным полем;
- узел доступен в палитре графа механик (раздел «Правила персонажа»), так что
  владение навыком можно собрать и вручную — для расы, предыстории, черты.

Значения узла — названия из справочника или ключи (как в `window.SKILLS`); в
лист владение попадает ключом.

## Заклинания расы

Раздел «Заклинания» описывает то, что раса даёт по части магии — например,
**высший эльф знает один заговор из списка волшебника** (Интеллект — его
заклинательная характеристика). Так и выглядит открытая запись SRD: один выбор
заговора, круг 0, классы «волшебник, wizard», характеристика «int».

- **Заклинания, известные сразу** — списком: название, круг, характеристика
  (шесть характеристик, «не указана» или «выбор игрока»). Заклинание добавляется
  кнопкой или перетаскиванием записи из справочника (принимается только категория
  «Заклинания»). Каждой характеристике соответствует свой узел `rule.spell_list`:
  список известных заклинаний идёт через проекцию графа, как навыки и языки.
  Для характеристики «выбор игрока» узел пишется без `ability` — значение
  подставляет мастер создания из выбора «Заклинательная характеристика».
- **Выбор игрока** — заголовок (то, что увидит игрок в мастере создания),
  круг, классы через запятую и характеристика. Пишется в `data.spell_choices`
  в том же виде, что наборы правил (`kind: 'spell'`, `filter: { level, classes }`).
- **Заклинательная характеристика** — режим: «наследуется от набора правил»
  (поле не пишется — у линий 2024 так работает набор родительской расы),
  «игрок выбирает из списка» (галочки характеристик, по умолчанию Инт/Мдр/Хар)
  или «не задана». Пишется в `data.spell_ability_choice`.

Данные записи **перекрывают набор правил**: если в записи есть `cantrips`,
`spell_choices` или `spell_ability_choice`, мастер создания берёт их вместо
соответствующей части набора `race_rules` (у линии — поверх родительской расы,
как и остальные поля). Поэтому правка в редакторе видна сразу, а пустой список
гасит пресетный заговор.

Заклинания из данных и из графа попадают в лист персонажа при сборке
(`CharacterBuilder.build`): заклинания расы выдаются известными и подготовленными,
характеристика берётся из узла, из выбора игрока или `raceSpellAbility`. Карточка
расы в справочнике показывает и известные сразу заклинания, и выбор заклинаний.

## Тесты

`tests/race-editor.test.cjs`:

- круг чтения/записи на живой записи SRD (эльф): скорость, языки, бонусы, навыки, черты;
- узлы правил обновляются на месте, связи условия редакции не рвутся;
- удаление и добавление бонуса характеристики перестраивает узлы;
- владение и выбор навыков: узлы плюс проекция графа на лист;
- черты: переименование, текст, создание и удаление программы;
- новая раса собирает валидный граф v2;
- заклинания: набор правил («Заговор высшего эльфа», известные сразу заклинания тифлинга), наследование линии от корня;
- запись заклинаний: узлы `rule.spell_list` по характеристикам, `data.cantrips`, `data.spell_choices`, `data.spell_ability_choice`, круг чтения и валидность графа;
- заклинания расы доходят до листа: известное сразу из данных и заклинание из узла графа;
- DOM-прогон: все восемь разделов, язык из списка, навык и заклинание перетаскиванием, новая черта, выбор заговора, сохранение.

`tests/skill-graph.test.cjs` — узел `rule.skill_proficiency`: записи навыков из
`data_seed/skills.json`, проекция владения, проверки параметров и палитра.

`tests/character-builder.test.cjs` — заклинания расы из данных записи: известные
сразу, выбор игрока в мастере создания и перекрытие набора правил.

```bash
node --test tests/race-editor.test.cjs tests/skill-graph.test.cjs
python3 tools/srd/build_skills.py --check
```
