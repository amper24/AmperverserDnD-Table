# Редактор расы

Отдельный конструктор расы по образу редактора класса: **Справочник → Расы →
«+ Создать свою запись»** или **«Редактировать» в карточке расы**. Код —
`static/race-editor.js` (`window.RaceEditor`), стили — те же `.ced-*`, что у
редактора класса (`static/style.css`).

## Разделы

| Раздел | Что правится |
|---|---|
| **Общее** | название (ru/en), редакция, размер, скорость, родительская раса (для разновидности), описание, возраст, рост и вес |
| **Характеристики** | фиксированные бонусы (+2, +1 …) по шести характеристикам |
| **Языки** | языки расы списком + отдельное примечание («Вы можете говорить, читать и писать на…») |
| **Навыки** | владение навыками (можно перетащить запись «Навыки» из справочника) и выбор игрока: сколько и из каких |
| **Владения** | владения по видам: доспехи, оружие, инструменты, своё |
| **Черты** | особенности расы: название и текст (кнопки бросков в тексте работают на листе) |
| **Подрасы** | список разновидностей (сами разновидности — отдельные записи с родительской расой) |

## Правила расы — узлы графа

Мастер создания персонажа читает правила расы из графа (`rule.*`), поэтому
редактор правит **и узлы, и сырые поля записи**:

| Что | Узел | Поле записи |
|---|---|---|
| скорость | `rule.speed` | `data.speed` |
| языки | `rule.languages` | `data.languages` (имена + примечание) |
| бонусы характеристик | `rule.ability_bonus` (по узлу на характеристику) | `data.asi` |
| владение навыком | `rule.skill_proficiency` | `data.skills` |
| выбор навыков игроком | `rule.skills` (id, count, options) | — |
| владения | `rule.proficiencies` (по узлу на вид) | — |
| черты | `action.program` (`group: 'traits'`) + `action.manual` | `data.traits` |

Узлы обновляются **на месте**: сохраняются их id и связи (например, условие
редакции `condition.edition` у бонуса характеристики). Пассивные блоки старого
формата (`action.passive` со скоростью, языками, `asi.*` и навыками)
синхронизируются вместе с узлами, иначе лист показал бы прежние значения.
Черта, переименованная в редакторе, сохраняет свою программу графа; удалённая
черта уносит программу и её текстовый узел.

Неизвестные редактору поля и прочие узлы записи (пассивные программы, условия,
свои группы) сохраняются как есть.

## Навыки и графы

Запись навыка (категория «Навыки») несёт свой граф с узлом
**`rule.skill_proficiency`** — тем же, что пишет редактор расы. Поэтому:

- навык, перетащенный в раздел «Навыки», попадает в узел `rule.skill_proficiency`;
- навык, перетащенный на лист персонажа, раздаёт владение через проекцию графа
  (`Mechanics.applyGraphRules`), а не отдельным полем;
- узел доступен в палитре графа механик (раздел «Правила персонажа»), так что
  владение навыком можно собрать и вручную — для расы, предыстории, черты.

Значения узла — названия из справочника или ключи (как в `window.SKILLS`); в
лист владение попадает ключом.

## Тесты

`tests/race-editor.test.cjs`:

- круг чтения/записи на живой записи SRD (эльф): скорость, языки, бонусы, навыки, черты;
- узлы правил обновляются на месте, связи условия редакции не рвутся;
- удаление и добавление бонуса характеристики перестраивает узлы;
- владение и выбор навыков: узлы плюс проекция графа на лист;
- черты: переименование, текст, создание и удаление программы;
- новая раса собирает валидный граф v2;
- DOM-прогон: все семь разделов, язык из списка, навык перетаскиванием, новая черта, сохранение.

`tests/skill-graph.test.cjs` — узел `rule.skill_proficiency`: записи навыков из
`data_seed/skills.json`, проекция владения, проверки параметров и палитра.

```bash
node --test tests/race-editor.test.cjs tests/skill-graph.test.cjs
python3 tools/srd/build_skills.py --check
```
