# Механики v1: общий конструктор блоков

## Интерфейс

Предметы, заклинания, умения, расы, классы, предыстории, монстры, состояния,
NPC и сведения используют один редактор. Описание — отдельно от программы.
В программе есть именованные действия, последовательность цветных блоков,
перетаскивание, перемещение кнопками, копирование, отключение и проверка.
Кубики задаются количеством, гранями, постоянным бонусом и модификатором.
Произвольная **формула кубиков**, не JavaScript, оставлена дополнительной опцией.

Типы: атака, урон, лечение, временные хиты, отдельный бросок, спасбросок цели,
расход, выдача предмета, состояние, изменение показателя, проверка условия,
ручное правило и пассивный параметр при создании. Ветвление плоское:
«всегда», «попадание / провал спасброска», «промах / успешный спасбросок».
Для ветвления по атаке включите сравнение с КД цели. Циклов и исполняемого кода нет.
Пассивные параметры располагаются в отдельном действии с соответствующим триггером.

Готовые рецепты: зелье → лечение → флакон; атака → урон;
сырьё → предмет; ячейка → лечение. Рецепт добавляет **новое** действие,
не удаляя уже созданные. Удалите лишнее действие, если заменяете старое.

Для рас, классов и предысторий рецепты свои, потому что они описывают создание
персонажа: **бонус характеристики** (пассивный блок `asi.*`), **навыки на выбор**
(пассивный блок `skills` со списком), **умение** (ручной блок в действии)
и **владение** (пассивный блок `armor` / `weapons`). Новая запись этих категорий
создаётся уже с шаблоном `Mechanics.starter(category)`: пассивные параметры
(скорость, бонус характеристики и языки у расы; кость хитов, спасбросок и выбор
навыков у класса; навыки и языки у предыстории) плюс заготовка умения.
Шаблон — обычные блоки: их можно удалить или заменить.

## Количество и связи

- Количество — целое 0…1 000 000, расход/выдача одним блоком — 1…10 000.
- Нулевая стопка остаётся с прежним UID, чтобы не ломать привязки.
- Расходовать можно себя, конкретный UID другого предмета или подходящие
  стопки по метке. Явная ссылка не заменяется случайной похожей стопкой.
- Метка сопоставляется с `ammo_tag` или элементом `tags`. Непустые стопки
  расходуются по порядку. Заряды недоступны при нулевом количестве предмета.
- Расход «за атаку» размещается **перед** атаками и срабатывает перед каждой
  действительно выполняемой последующей атакой. Бросок урона не расходует патрон.
- Заряды — общий запас **стопки**, не бесплатные копии запаса на каждый экземпляр.
  Разделение и частичная передача пропорционально делят текущий и максимальный
  запас с округлением вниз в отделяемую часть; остаток остаётся исходной стопке.
  Для независимых перезаряжаемых предметов храните отдельные записи.
- Выдача использует сохранённую копию шаблона, а не копирует текущую стопку
  источника. Механики выданного предмета автоматически не запускаются.
- Совпадающие обычные шаблоны объединяются без сравнения только по имени:
  должны совпадать все свойства, кроме UID, количества и состояния экипировки.
  Настроенные/экипированные предметы и предметы с зарядами автоматически не сливаются.
- Базовые стандартные боеприпасы импортируются упаковками с поштучным весом:
  стрелы/болты/снаряды пращи — 20, иглы — 50, огнестрельные пули — 10.
  Цена исходного справочника остаётся ценой упаковки. Старые стопки не умножаются.
- Ячейки используют существующую модель `spells.slots[level].{max,used}`;
  использования умения — `uses.cur`. Указание ёмкости само по себе не добавляет
  расход: он должен быть явно задан блоком.

## Исполнение

`POST /api/characters/:id/inventory` принимает:

```json
{
  "op": "program",
  "request_id": "уникальный UUID запроса",
  "source_kind": "item",
  "source_uid": "UID сохранённого предмета",
  "program_id": "ID действия",
  "target_id": "ID выбранного персонажа или самого владельца",
  "acknowledged": false,
  "mode": "normal",
  "gm_only": false
}
```

`source_kind`: `item`, `spell`, `feature`. Программу сервер читает только из
сохранённого листа. Передавать исполняемые блоки в запросе нельзя.
Изменения считаются на копиях; при любой ошибке исходные листы не изменяются.
Расход, результаты кубиков, эффекты, выдача, чат и запись идемпотентности
сохраняются в одной транзакции с revision CAS. Повтор **того же request_id**
возвращает прежний результат, а не исполняет цепочку заново.
Кнопка повторения в журнале открывает путь исполнения программы, а не бесплатный
повтор её кубиков. Отдельная проверка кубика в справочнике явно подписана
«без эффектов» и ничего не расходует.

Лечение ограничено максимумом хитов. Временные хиты берут максимум, не суммируются.
Применяемый урон сначала снимает временные хиты, затем обычные, до нуля.
`@spell_mod` — только модификатор характеристики; `@spell` — бонус атаки,
включающий мастерство. Урон по умолчанию **только бросается**, не применяется:
включение изменения цели — явная настройка блока.

Цель: сам владелец либо другой персонаж **той же кампании, доступный для изменения**.
Прав на просмотр чужого листа недостаточно. Мастер может менять листы кампании;
игрок не получает возможности молча менять хиты другого игрока или противника.
Выбор цели не обходит эти серверные ограничения. Сценические токены монстров
не являются листами персонажей: их статблок показывает блоки/отдельные броски,
но этот endpoint не изменяет здоровье токена.

## Стандартная библиотека и совместимость

Все **2 499** записей SRD 2014/2024 содержат `data.mechanics.version = 1`.
Скрипт `python3 tools/srd/mechanics.py` воспроизводимо обновляет JSON; он также
вызывается сборщиком SRD. Сводка: `docs/mechanics-migration.json`.
Исходные поля не удалены и не изменены: старые интеграции и текст правил сохранены.

При старте сервер добавляет новые стандартные записи и дописывает механики в
существующие записи, **только если** их имя и исходные данные совпадают с поставкой.
Записи с уже существующими механиками и изменённые пользователем записи не
перезаписываются. При редактировании старого документа применяется адаптер
в конструкторе; сохранение переводит его на блоки. Отмена не меняет оригинал.
Старые копии предметов на листах не заменяются автоматически новой библиотекой.
Для них откройте редактор или импортируйте свежий шаблон, проверив количество.

Пассивные параметры проецируются при создании персонажа без повторного накопления.
Программы расовых особенностей, классовых умений и предысторий сохраняются
при переносе на лист. Редактор вложенной особенности также использует блоки.

Отдельно от блоков раса, класс и предыстория могут описать **выбор «либо / либо»**
(`data.choices`): группа вариантов, из которых игрок выбирает один или несколько
при создании (бонус характеристики, навык, язык, умение, владение). Это данные
создания, а не программа: они не исполняются на листе и не расходуют ресурсы.
Схему проверяют `mechanics::validate_choices` на сервере и
`CharacterBuilder.validateChoices` в редакторе; описание —
в `docs/character-builder.md`.

**Класс и раса — не объекты на карте.** В их редакторе есть только изображение
карточки; поле токена скрыто, а ранее сохранённый `token_asset_id` удаляется
на сервере при сохранении записи. Токены остаются у предметов, заклинаний,
монстров, NPC и самого персонажа.

### Важно: покрытие схемой ≠ полная автоматизация D&D

Автоматизированы общие операции и явные рецепты: базовое оружие,
расход боеприпасов, зелья лечения (включая разновидности 2014), базовые
«Лечение ран» и «Лечащее слово» с различием редакций, состояния и числовые эффекты.
Прочие зелья расходуются, но их специальные эффекты объясняются ручным блоком.

Сложные стандартные правила представлены **ручными блоками** с подтверждением.
Старые извлечённые из текста атаки/урон сохранены отдельными опциональными
блоками-бросками, а не автоматически склеены: среди них встречается отложенный
и альтернативный урон. Например, дополнительная кислота аболета не становится
безусловным уроном каждого попадания.

Не автоматизированы: сопротивления/иммунитеты, длительности и окончание эффектов,
концентрация, дальность и геометрия областей, выбор нескольких целей, повышение
круга, масштабирование заговоров, смерть/спасброски от смерти, доступность действия
по экономике хода и полная семантика всех классовых особенностей.
Проверяйте эти правила вручную; для иной последовательности создавайте явную программу.

## Проверки

- `node --test tests/*.test.cjs`: JS-инварианты, миграция, стартовые шаблоны
  расы/класса/предыстории, схема выбора, вся стандартная библиотека.
- `tests/mechanics.browser.cjs`: реальный редактор, рецепт, порядок, сохранение,
  десять категорий, мобильная ширина; API в браузерных проверках заменён фикстурами.
- Rust unit tests в `src/mechanics.rs`, `src/inventory.rs`.
- `tests/inventory-api.py`, вызываемый `scripts/smoke.sh`: реальный API,
  атомарное зелье, повтор запроса, откат поздней ошибки.

Локальная среда не содержит Cargo/rustc, поэтому серверные проверки выполняются
GitHub Actions: release-сборка, Rust unit tests, настоящий API на временных
SQLite/MySQL БД, Windows-сборка и проверка установочных/запускных скриптов.
Перед публикацией требуется зелёный CI на точном коммите релиза.
