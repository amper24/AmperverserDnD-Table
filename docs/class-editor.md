# Редактор класса

Отдельный конструктор класса: **Справочник → Классы → «+ Создать свою запись»**
или **«Редактор класса» в карточке любого класса** (вместо общего редактора записи).
Код — `static/class-editor.js` (`window.ClassEditor`), стили — `.ced-*` в `static/style.css`.

## Зачем

Запись класса — не один текст: это таблица уровней, список навыков, языки,
стартовое снаряжение, подклассы и режим заклинаний. Раньше всё это лежало одним
полем `data`, и править его приходилось JSON. Теперь у каждого смысла свой раздел:

| Раздел | Что правится |
|---|---|
| **Общее** | название (ru/en), редакция, кость хитов, спасброски, главная и заклинательная характеристика, доспехи/оружие/инструменты, описание |
| **Уровни 1–20** | бонус мастерства, заговоры, известные и подготовленные заклинания, ячейки 1–9 кругов по каждому уровню; кнопка «умения» раскрывает список умений уровня с текстами |
| **Навыки** | сколько навыков выбирает игрок и из какого списка; навыки добавляются селектом **или перетаскиванием записи «Навыки» из справочника** |
| **Языки** | фиксированные языки класса и сколько языков игрок выбирает дополнительно |
| **Снаряжение** | блоки «выдаётся всегда» и «выбор варианта (a)/(b)/(c)»; строки — предмет (с количеством), золото или «по выбору» (фильтр каталога). Предмет можно перетащить из справочника прямо в строку |
| **Подклассы** | название, английское название, надпись, описание и умения по уровням |
| **Заклинания** | тип заклинателя, что получает на 1 уровне, формула подготовленных, книга (старт и за уровень) |

Под списком снаряжения есть свёртка «Так это увидит мастер создания» — сгенерированный
текст, который реально читает парсер мастера персонажа.

## Что пишется в запись

| Поле записи | Кто читает |
|---|---|
| `data.skills = { choose, from }` | мастер создания (`CharacterBuilder.skillsState`) |
| `data.features` / `data.feature_texts` | лист, повышение уровня (`LevelUp.classFeaturesAt`) |
| `data.starting_equipment` | `CharacterBuilder.parseEquipmentText` |
| `data.equipment_blocks` | сам редактор (структура блоков для повторного открытия) |
| `data.languages_fixed` / `data.languages_extra` | `CharacterBuilder` (владения) и `builder-dialog` (шаг «Навыки») |
| `data.subclasses` | повышение уровня, мастер создания |
| `data.caster` | `ClassRules` (режим заклинаний) |

Неизвестные редактору поля прежней записи (`mechanics`, `i18n`, `folder`, изображения)
сохраняются как есть: редактор дописывает поверх копии `data`. Таблица развития старого
формата (`data.progression`) при первой правке уровней переносится в узел
`rule.class_progression` и из данных удаляется — источников правды остаётся один.

## Граф механик

Правила класса живут в узлах записи, и редактор правит их на месте — так же, как
редактор расы (`docs/race-editor.md`). Узлы с постоянными id не пересоздаются, поэтому
связи (условия по редакции) не рвутся, а значения, которых не касались, не переписываются:
сохранение записи SRD без правок не меняет ни один узел.

| Раздел | Узлы |
|---|---|
| Общее | `rule.hit_die`, `rule.saving_throws`, `rule.spellcasting` |
| Владения | `rule.proficiencies` по видам «Доспехи», «Оружие», «Инструменты» |
| Навыки | `rule.skills` (id `classSkills`; пустой список — «любой навык») — это правило читают мастер создания (`CharacterBuilder.skillsState` через `ClassRules.skillsOf`), карточка класса и мастер повышения уровня (ограничение экспертизы) |
| Языки | `rule.languages` |
| Уровни | `rule.class_features` (умения по уровням), `rule.class_progression` (таблица 1–20) |
| Заклинания | `table.caster` в `rule.class_rules` (мультикласс не трогается) |

Узел ищется по типу, а не по id: у записей SRD свои id (`class_features`,
`class_progression`), и второй узел того же правила не создаётся. Таблица развития
пишется по уровням: правленые строки обновляются, строки узла со своими колонками
(«Ярости», «Урон ярости») остаются как были, а если таблицы в записи не было — она
пишется целиком. Пустые ячейки и pact-поля не пишутся вовсе — так же хранит таблицы
набор SRD. «—» в поле владений значит «нет владений»: узел для такого вида не создаётся.
В блоке заклинателя сохраняются ключи, которых редактор не знает (`picker`), а число
стартовых подготовленных заклинаний остаётся числом.

Уровень получения подкласса не задаётся отдельным полем: он считается по самому
младшему уровню в умениях подкласса — так же, как это делает `LevelUp.subclassLevel`.
Признак «Увеличение характеристик» — это название умения (его ищет набор
`feature_rules`), поэтому в редакторе есть кнопка быстрого добавления такого умения.

## Навыки — объект справочника

Навыки стали отдельной категорией справочника (`skill`): 18 записей сеются файлом
`data_seed/skills.json` (источник «Навыки», вне редакций — видны в фильтре любой редакции).
Каждая запись: `data.key` (ключ из `window.SKILLS`), `data.ability`, `data.name_en`, описание
и английский слой перевода.

Запись навыка:

- перетаскивается **в редактор класса** (тип `application/x-skill`) — попадает в список выбора;
- перетаскивается **на лист персонажа** — добавляет владение навыком (повторно не добавляется);
- открывается карточкой в справочнике, как любая другая запись.

Свои навыки создаются обычной кнопкой «+ Создать свою запись» в категории «Навыки».

## Тесты

`tests/class-editor.test.cjs`:

- круг `readState → writeData` без потерь (умения, таблица уровней, подклассы, языки, кастер);
- правила читаются из узлов: кость хитов, спасброски, владения, навыки, умения и заклинатель;
- правки редактора доходят до листа через узлы графа (`CharacterBuilder.build`);
- сохранение без правок не переписывает узлы SRD (варвар, бард, монах 2014 и волшебник 2024:
  включая `picker` в блоке заклинателя и «—» в владениях);
- правка заклинателя уходит и в данные, и в узел, не теряя мультикласс и чужие ключи;
- таблица развития: правленые уровни уходят в узел, нетронутые — остаются строками SRD,
  таблица старого формата переносится из данных в узел;
- блоки снаряжения → текст → разбор тем же парсером, что у мастера создания;
- навыки: ключ по названию, запись справочника как источник;
- класс из редактора собирает лист персонажа (навыки, умение 1 уровня, язык, снаряжение);
- DOM-прогон: открытие редактора, все семь разделов, добавление навыка селектом и
  перетаскиванием, правка уровней и снаряжения, сохранение (граф после сохранения валиден).

```bash
node --test tests/class-editor.test.cjs
```
