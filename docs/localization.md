# Локализация записей справочника

Записи справочника хранятся на **базовом языке набора** — для встроенного SRD и наборов по умолчанию это русский (`i18n::DEFAULT_LANG`). Переводы лежат **внутри самой записи** в слое `data.i18n.<язык>`:

```json
{ "name": "Огненный шар", "data": { "desc": "…", "i18n": { "en": { "name": "Fireball", "desc": "…" } } } }
```

Поддерживаемые языки — `ru` и `en` (`i18n::LANGS` в `src/i18n.rs`); `norm_lang` нормализует коды вида `en-US`, `ru_RU`.

## Слой перевода — это «разница», не копия

Алгоритм `i18n::merge(base, overlay)` (тот же в `tools/srd/localize.py` — `merge`/`diff`):

* ключ **без** `!` — значение накладывается поверх базового; объекты сливаются рекурсивно;
* ключ **с суффиксом** `!` (например `"properties!"`) — значение заменяет базовое целиком;
* массивы объектов, у которых у **всех** элементов есть строковое поле `id` (программы и блоки механик), сливаются **по `id`** (элемент с тем же `id` мержится, новый — добавляется в конец);
* остальные массивы заменяются целиком;
* если база или слой — не объект, слой возвращается как есть.

## Что видит клиент

Сервер отдаёт запись в виде на языке просмотра: слой `i18n` снят, поверх базы наложен перевод (`i18n::view`). В данные добавляется метка `i18n_view` — **такие данные нельзя сохранять обратно**: `create`/`update` отклоняют их с подсказкой запросить запись с `?raw=1` (`check_editable`). «Сырая» запись (база + слои) — только по `GET /api/compendium/:id?raw=1`, её и правят редакторы (`API.rawEntry` в `static/core/common.js`).

Особый случай: английское название хранится только в `i18n.en.name`; в виде просмотра оно дополнительно отдаётся полем `name_en` (редакторы читают `d.name_en || d.i18n?.en?.name`).

## Проверки

* При сохранении слой `i18n` валидируется (`i18n::validate`): объект вида `{ "en": {…} }`, только известные языки, разумный размер; `i18n_view` в сохраняемых данных — ошибка.
* `node tools/srd/integrity.cjs` проверяет переводы данных: наличие английского слоя `data.i18n.en`, отсутствие кириллицы в английских названиях, отсутствие латиницы в русских, известные языки (`src/i18n.rs` `LANGS`).
* `tests/i18n.test.cjs` покрывает `merge`/`view` на стороне серверного алгоритма и данные переводов.

## Где что лежит

| Часть | Файл |
|---|---|
| серверный merge/view/validate, `LANGS` | `src/i18n.rs` |
| генератор переводов: `merge`/`diff` между RU и EN | `tools/srd/localize.py` |
| ручные переводы терминов/названий | `tools/srd/i18n_terms.py`, `tools/srd/i18n_manual.py`, `tools/srd/i18n_md.py`, `tools/srd/ru_names.py`, `tools/srd/ru_spells.json` |
| «сырая» запись и `name_en` на клиенте | `static/core/common.js` (`API.rawEntry`) |
| встроенные данные со слоями `i18n` | `data_seed/srd_2014.json`, `data_seed/srd_2024.json`, `data_seed/feats_*.json` |
