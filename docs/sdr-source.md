# Базовый справочник (SDR): источник, кэш и обновление

Откуда сервер берёт стартовые данные (монстры, черты, навыки, встроенные ассеты), что лежит
на диске и как обновить справочник без пересборки. Код: `src/store/sdr_source.rs`,
`src/store/seed.rs`, `src/config.rs` (`SdrCfg`), `src/api/admin.rs`.

## Источники по приоритету

| Источник | Условие | Что читает |
|---|---|---|
| `GitSdrSource` | `sdr.enabled: true` (по умолчанию) | кэш Git-репозитория, папка `data_seed/` |
| `LocalSdrSource` | `sdr.enabled: false` и существует `sdr.local_path` | папка на диске |
| `EmbeddedSdrSource` | всё остальное | файлы, вкомпилированные в бинарник (`RustEmbed`) |

## Что попадает в кэш

В кэш (`sdr.clone_dir`, по умолчанию `.sdr_cache/`) клонируется **только `data_seed/`**:

```sh
git clone --depth 1 --filter=blob:none --sparse --branch main <url> .sdr_cache
git -C .sdr_cache sparse-checkout set --no-cone 'data_seed/'
```

`--filter=blob:none` не даёт скачивать блобы, которых нет среди выбранных путей, поэтому
`.git` такого кэша — единицы мегабайт. Шаблон задаётся в режиме `--no-cone`: конусный
sparse-checkout (`--sparse` по умолчанию) всегда оставляет в рабочем дереве файлы верхнего
уровня (`Cargo.toml`, `README.md`, `*.bat`), а `--no-cone 'data_seed/'` убирает и их.
Замеры на текущем репозитории: кэш — 25 МБ (23 МБ данные + 2.8 МБ `.git`), полный мелкий
клон — 37 МБ, обычный клон с историей — больше.

Исходники проекта (`src/`, `static/`, `tests/`, `docs/`) в кэш не попадают. Если git или
сервер не поддерживают partial clone, включается обычный `git clone --depth 1`, после
которого рабочее дерево всё равно сужается до `data_seed/`.

Кэш, созданный прежними сборками (полный клон всего проекта), сужается до `data_seed/`
при первом же запуске — но только если это собственный мелкий клон (`--depth 1`) в
`sdr.clone_dir`; рабочий репозиторий пользователя не трогается.

## Когда данные забираются из Git

Ключ `sdr.update` (переменная `SDR_UPDATE`):

| Значение | Поведение |
|---|---|
| `once` (по умолчанию) | клон создаётся один раз, если кэша ещё нет. Дальше сеть не используется: сервер стартует офлайн с тем, что уже скачано |
| `always` | плюс `git pull --ff-only` кэша при каждом запуске. Неудачный pull — предупреждение в лог, работа продолжается на локальной копии |

Независимо от режима, клон/обновление выполняются **не более одного раза за процесс**:
`read_file` вызывается на каждый файл, и сетевой вызов на файл недопустим.

## Если источник недоступен

При старте ошибка источника не роняет сервер: пишется предупреждение и справочник
заполняется вкомпилированными данными (тот же `EmbeddedSdrSource`). Явная перезаливка
(`POST /api/admin/reseed` / `POST /api/admin/sdr`) в этом случае вернёт ошибку — чтобы
проблема с сетью или репозиторием была видна, а не скрыта.

## Переподгрузка со страницы root

`POST /api/admin/sdr` (только `is_root`) — забирает свежие данные из Git (тот же `git pull`,
режим `always` принудительно), удаляет базовые записи справочника и заливает их заново.
Ответ: `{"ok": true, "entries": <число записей>, "source": "git" | "local"}`.

В интерфейсе это кнопка **«Обновить из Git»** на странице «Администрирование»
(`static/pages/lobby.js`, раздел root). Рядом — **«Пересоздать базовый справочник»**
(`POST /api/admin/reseed`), которая перезаливает данные из текущего источника без обращения к сети.

Чего обе операции не делают: не восстанавливают удалённые вручную базовые записи по одной и не
трогают пользовательские наборы — они удаляют и заливают базовый справочник целиком,
поэтому правки базовых записей теряются (в подтверждении об этом сказано).

## Отпечаток и повторное заполнение

`seed_compendium` считает отпечаток (хэш по содержимому шести файлов `SEED_FILES`) и пишет его
в `seed_state['compendium']`. Если отпечаток совпал, справочник не перезаливается — поэтому
старт с готовой базой не требует ни сети, ни записи в БД. Встроенные ассеты сеются по одному
разу на файл (`builtin_seeds`), новые файлы манифеста добавляются в существующую базу.

## Конфигурация

```yaml
sdr:
  enabled: true            # SDR_ENABLED
  git_url: https://github.com/amper24/AmperverserDnD-Table.git  # SDR_GIT_URL
  git_branch: main         # SDR_GIT_BRANCH
  clone_dir: .sdr_cache    # SDR_CLONE_DIR — сюда попадает только data_seed/
  update: once             # SDR_UPDATE: once | always
  local_path: data_seed    # SDR_LOCAL_PATH — источник, когда Git отключён
```

Неизвестное значение `sdr.update` приводит к предупреждению при старте и режиму `once`.
