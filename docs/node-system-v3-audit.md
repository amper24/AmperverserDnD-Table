## Отклонения и ограничения (осознанные)

1. **`flow.if` остаётся статическим**: значения `data.result`/`data.sheet` в нём дают 0,
   потому что ветвление компилируется до исполнения. Динамические условия работают на
   входах блоков (`condition`), а не на ветвлении. Так проще и предсказуемее; при
   необходимости ветвление по результатам делается двумя блоками с `condition`.
2. **Блоков действий 7, а не ≤6**: `manual` — это текстовое правило, а не действие;
   без него не выразить справочные механики SRD. Итоговая палитра: 7 блоков + поток.
3. **Ручные правила и динамические условия**: клиентский предпросмотр статический,
   поэтому manual-блок, скрытый в предпросмотре, но выполнимый на сервере, требует
   подтверждения. Это описано в docs; в текущих данных таких цепочек нет.
4. **`equipment.browser.cjs`** падает на `.roll-mode-menu` и на чистом HEAD — это
   предсуществующий дефект теста/среды, к v3 не относится.
5. **`data.result` читает результаты прошлых действий**: собственный итог текущего
   действия в середине цепочки недоступен (результаты пишутся после выполнения).
   Для «своего» итога используйте `action.roll` → `condition.hit`/`data.compare` по
   входу, либо предыдущее действие предмета.

## Что осталось (приоритеты)

1. Ветвление по результатам (`flow.if` с рантайм-условием) — если понадобится.
2. Показ истории результатов действий в карточке предмета (сейчас доступны в ответе
   каста и через `data.result`).
3. Починить `equipment.browser.cjs` (не связано с v3).
