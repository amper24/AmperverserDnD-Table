# Аудит редакторов: что можно создать и чем редактировать

Дата проверки: 2026-10-11. Проверено чтением кода (`static/*.js`) и содержимого наборов (`static/presets/`).
Цель: у каждого создаваемого элемента должен быть удобный редактор, а правила должны жить в одной системе наборов и узлов.

## 1. Записи справочника (`compendium.js` → `editEntry`)

| Категория | Редактор | Что можно задать | Связь с правилами наборов | Вывод |
|---|---|---|---|---|
| Предмет (`item`) | `editItem` | поля, механики, хват, расход | — | ок |
| Заклинание (`spell`) | `editSpell` | уровень, школа, механики | `spell_schools` (словарь) | ок |
| Раса (`race`) | `editGeneric` | название, описание, изображение, граф механик | `race_rules` по `data.name_en` | **разрыв**: поля `name_en` в редакторе нет, связь с правилами не задать |
| Класс (`class`) | `editGeneric` | то же | `class_rules`, `class_progression`, `multiclass_slots` по `name_en` | **разрыв**: правила классов не редактируются, `name_en` не задать |
| Предыстория (`background`) | `editGeneric` | то же | — (граф) | ок для описания |
| Черта (`feat`) | `editGeneric` | то же | `feat_rules` по `name_en` | **разрыв**: правила черты не редактируются, `name_en` не задать |
| Состояние (`condition`) | `editGeneric` | то же | `conditions` (словарь) | **разрыв**: новое состояние не попадает в словарь |
| Лор (`lore`) | `editGeneric` | то же | — | ок |
| Бестиарий (`monster`) | `editGeneric` + блок статов | характеристики, атаки | — | ок |
| NPC (`npc`) | `editGeneric` + блок статов | роль, секреты, статы | — | ок |

Итог по справочнику: предметы и заклинания имеют полноценные редакторы; расы, классы, черты и состояния создаются только как описание с графом. Их правила (выборы, прогрессия, владения, слоты) можно задать только импортом JSON-набора.

## 2. Наборы данных (`presets.js` → `openManager`)

Кнопка «Наборы данных» есть только в редакторе графов (`mechanics-graph.js`). Менеджер умеет: показать список наборов с числом элементов, импортировать JSON-текст или файл, удалить свой набор. Редактирования элементов нет ни для одного вида.

| Вид набора | Наборов / элементов (встроенные) | Потребитель | Редактор элементов |
|---|---|---|---|
| `race_rules` | 2 / 17 | мастер персонажа | нет (JSON) |
| `class_rules` | 2 / 24 | мастер персонажа, повышение уровня, граф | нет (JSON) |
| `class_progression` | 2 / 24 | мастер, граф | нет (JSON) |
| `multiclass_slots` | 2 / 2 | лист, повышение | нет (JSON) |
| `feat_rules` | 2 / 15 | мастер, повышение | нет (JSON) |
| `feature_rules` | 2 / 26 | повышение | нет (JSON) |
| `conditions` | 1 / 16 | лист, граф, таблица | нет (JSON) |
| `spell_schools` | 1 / 8 | повышение, модули | нет (JSON) |
| `languages` | 1 / 17 | мастер, граф | нет (JSON) |
| `enemy_types` | 1 / 14 | повышение (избранный враг) | нет (JSON) |
| `mechanic_templates` | 1 / 31 | конструктор блоков | нет (JSON) |
| `mechanic_starters` | 1 / 3 | мастер создания | нет (JSON) |
| `equipment_text_rules` | 1 / 27 | разбор снаряжения | нет (JSON) |
| `equipment_pick_rules` | 1 / 28 | выбор снаряжения | нет (JSON) |
| `block_defaults` | 1 / 12 | конструктор блоков | нет (JSON) |
| `item_preset` | 1 / 6 | создание предметов | нет (JSON) |
| `spell_preset` | 1 / 5 | создание заклинаний | нет (JSON) |
| `graph_starter` | 1 / 5 | новый граф | нет (JSON) |

Что видно из таблицы:
- 18 видов наборов, ни у одного нет редактора элементов; создание возможно только текстом JSON.
- `enemy_types` и `spell_preset`/`item_preset` читаются, но их состав нигде не виден пользователю.
- Пользователь не видит, какие элементы набора он переопределяет; при повторном импорте того же `id` набор заменяется целиком.

## 3. Прочее

- Узлы графа: палитра с категориями (`node-menu.js`) и карточка с параметрами (`node-params-form.js`). Полный обход всех видов узлов в этом аудите не проводился.
- Персонажи, кампании, наборы справочника, папки, пользователи: создаются через свои формы; в этом аудите не проверялись.

## 4. Статус исправлений (после правок того же дня)
- Связывание: раса, класс, черта, состояние — блок связи в редакторе записи (`presets-editor.js`).
- Редактор элементов наборов — окно «Наборы данных» со списком и формой; доступно из справочника и редактора графов.
- Пункты 1–3 ниже выполнены; пункт 4 (тест на наличие редактора у каждого вида) — не сделан.

## 5. Предлагаемый порядок исправления (исходный)

1. Поле `name_en` в `editGeneric` для рас, классов, черт, состояний (связь с наборами).
2. Редактор элементов набора: список элементов, форма по виду (поля `table` описываются схемой вида), сохранение во «свой» набор без правки JSON.
3. Кнопка «Наборы данных» доступна из справочника и мастера, а не только из графа.
4. Проверка, что у каждого вида набора есть потребитель и редактор; тест, который падает при новом виде без редактора.
