# Виртуальный стол: слои, карты, туман войны, линейка, участники

Стол — canvas-приложение в `static/table.js` (сцены, токены, туман, рисование) и
страница `static/table.html` (участники). Чистая логика вынесена в
`static/table-model.js`: файл не трогает DOM и сеть, поэтому проверяется
юнит-тестами (`tests/table-model.test.cjs`), а `table.js`, `app.js` и
`table-page.js` используют его как единственный источник правил.

Порядок загрузки: `common.js → asset-kinds.js → table-model.js → table.js`
(`static/index.html`, слой 5). `table-model.js` зависит только от
`AssetKinds.LAYER`/`layerOrder`.

## Слои

Раньше порядок слоёв был фиксированным списком (`AssetKinds.layerOrder`), теперь
он живёт в сцене:

```js
scene.layers = [
  { id: 'map', name: 'Карта', order: 0, hidden: false, locked: false },
  { id: 'prop', name: 'Объекты', order: 1 },
  // …
  { id: 'custom-1', name: 'Декорации', order: 8 },
]
```

* **Дефолт** — ровно прежний `LAYER_ORDER` (`map, prop, mount, character,
  attachment, drawing, text, note`) с прежними id и подписями. Старая сцена без
  `scene.layers` и старые элементы со старыми id работают как раньше.
* **Порядок отрисовки** — `order` (меньший рисуется первым, то есть «ниже»),
  затем `z` элемента. Сетка рисуется над всеми картами, но под остальными
  объектами.
* **Неизвестный слой** у элемента (слой удалили, сцена пришла от другого
  клиента) попадает на слой `prop` и по порядку, и по фолбэку `Table.getLayers()`;
  элемента никто не теряет.
* **Видимость** (`hidden`): игроки не видят элементы слоя; мастер видит их
  полупрозрачными.
* **Блокировка** (`locked`): игрок не может выбрать/сдвинуть элементы слоя,
  мастер может.
* **Активный слой** (`Table.setActiveLayer`) — куда попадают клики и загрузки
  файлов; у игрока доступен только слой персонажей (так же ограничен сервер).
* **Панель «Слои»** (боковая панель стола): порядок (выше/ниже), переименование,
  «+ Слой», удаление **пустого** слоя (последний удалить нельзя), видимость,
  блокировка, выбор активного. Селектор слоя в шапке стола строится из
  `scene.layers` (`app.js` → `Table.getLayers()`).
* **Синхронизация** — `scene.layers` часть сцены: `Table.setLayers(list)` шлёт
  `scene_update {layers}` (только мастер), сервер валидирует (до 32 записей,
  id `[a-z0-9_-]`, уникальные, имена до 64 символов, `order` пересчитывается),
  сохраняет в `scenes.layers` и рассылает всем. Битый список игнорируется и не
  затирает текущий.

## Карты

Карта — обычный элемент слоя `map`: `{ layer: 'map', z, data: { type: 'image',
asset_id, x, y, w, h } }`. Карт может быть несколько (этажи, области,
подземелья); ни одна не заменяет другую и подтверждение «Заменить текущую
карту?» больше не показывается.

* **Активная карта** — `scene.active_map_id` (id элемента слоя `map`). Выбор:
  ПКМ по карте → «Сделать активной», кнопка в панели свойств карты, список
  «Карты сцены» в панели «Сцены» (мастер). Активная карта обведена жёлтым
  пунктиром (когда карт несколько и вы мастер).
* **Совместимость**: если `active_map_id` пуст (старая сцена) и карта одна —
  она считается активной. Если id устарел (карту удалили) — активной снова
  становится единственная оставшаяся, иначе «активной нет».
* **`fitToMap` / «Вписать»** — по активной карте; если активной нет (несколько
  карт и ни одна не выбрана) — по объединению всех карт; если карт нет — по
  прежней сетке 20×20 клеток. «Вписать» есть в контекстном меню карты и в панели
  свойств.
* **Туман войны** — у каждой карты своя маска (`scene.fog.by_map`), см. раздел
  «Туман войны» ниже; оверлей и панель показывают маску активной карты.
* **Перетаскивание и масштаб** — карта двигается как обычный объект на слое
  `map` (по умолчанию она не закреплена), в панели свойств задаётся имя и ширина
  в клетках (высота по пропорциям), поворот/«выше/ниже» работают как у токенов.
* **Удаление** любой карты не трогает остальные; активная карта снимается и на
  сервере (`scenes.active_map_id = NULL`).
* **Новая карта** из «Ассетов» кладётся в точку броска (левый верхний угол
  притягивается к сетке), сразу становится активной, вид вписывается по ней.

## Туман войны

Туман — это маска **на карту**, а не на весь холст. Модель живёт в
`static/table-model.js` (чистые функции, `tests/table-model.test.cjs`), рисует и
редактирует её `static/table.js`.

```js
scene.fog = {
  enabled: false,                    // «Показать игрокам»
  by_map: {                          // ключ — id элемента слоя map
    '<id карты A>': { shapes: [ { shape: 'rect', mode: 'reveal', points: [[0,0],[700,500]] } ] },
    '<id карты B>': { shapes: [ { shape: 'path', mode: 'reveal', points: [[100,100],[180,140]], width: 210 } ] },
  },
}
```

* **Фигура** — `{ shape, mode, points, width? }`: `rect` и `circle` (две точки),
  `polygon` (3–256 точек), `path` (мазок кисти: 2–2048 точек + `width` в мировых
  px). `mode` — `reveal` (открыть) или `hide` (скрыть). Порядок фигур важен:
  последняя фигура, накрывшая точку, задаёт её состояние.
* **Карта без маски (или с пустой маской) полностью скрыта.** «Открыто» только
  то, что открыли явно. «Открыть всё» создаёт прямоугольник по границам карты.
* **Обрезка по карте.** Маска рисуется только внутри прямоугольника активной
  карты; `rect`/`circle`/`polygon` при добавлении обрезаются по её границам
  (круг, пересекающий край, превращается в многоугольник), фигура целиком вне
  карты просто не добавляется; мазок сохраняет точки, но визуально и при
  проверке «открыто ли» тоже ограничен картой. Точка вне карты всегда считается
  скрытой.
* **Миграция старого формата.** Сцены до этой версии хранили глобальный
  `scene.fog.shapes`. При загрузке сцены (`Table.setScene`/`init`) он
  переносится в маску активной (или единственной) карты, а поле `shapes`
  исчезает — дальше код читает только `by_map`. Если карт несколько и активная
  не выбрана, переносить некуда: маска не создаётся (и туман не рисуется, пока
  карта не станет активной). После выбора карты мастер рисует маску заново или
  нажимает «Открыть всё» — прежняя картина не восстанавливается, потому что
  старый туман не был привязан ни к одной карте.

### Инструменты (панель «Туман», только мастер)

| Кнопка | Клавиша | Что делает |
| --- | --- | --- |
| Кисть | `1` | мазок выбранного размера (1–10 клеток) |
| Прямоугольник | `2` | протяжка — прямоугольник |
| Круг | `3` | протяжка — круг/овал (радиус = расстояние) |
| Ластик | `4` | та же кисть, но в **обратном** режиме (стирает нарисованное) |
| Открыть / Скрыть | — | режим новых мазков; **Shift** временно переворачивает его |
| Размер кисти | `[` `]` | 1–10 клеток (ширина мазка = клетки × размер клетки) |
| Открыть всё | — | одна фигура-прямоугольник по границам активной карты |
| Скрыть всё | — | маска карты очищается (карта снова скрыта целиком) |
| Отменить мазок | `Ctrl+Z` | отмена последнего мазка (когда активен туман) |
| Показать игрокам | — | `scene.fog.enabled`: показывать ли туман игрокам |

* Панель открывается клавишей **F** (или кнопкой тумана). Инструмент/режим
  переключаются и кнопками панели, и клавишами.
* **Предпросмотр под курсором**: у кисти и ластика — кружок радиуса мазка (он же
  заменяет системный курсор), у фигур — точка-затравка, а во время протяжки
  виден полупрозрачный черновик фигуры.
* **Подсказка** внизу стола показывает инструмент, размер, режим, имя активной
  карты, число фигур `N/200` и состояние «Показать игрокам».
* **Отмена** — стек на карту, до 20 шагов (`TableModel.pushUndo`/`undoStep`);
  стек живёт в памяти клиента и не синхронизируется.
* **Ограничения маски**: до 200 фигур на карту (как на сервере) — при
  превышении новый мазок отклоняется с сообщением.

### Кто что видит

* **Мастер** всегда видит собственный оверлей: полупрозрачную (55 %) маску над
  активной картой — постоянно, если включено «Показать игрокам», и в режиме
  тумана (F) даже с выключенным флажком. В режиме тумана к нему добавляются
  жёлтая рамка карты и контуры нарисованных фигур. Оверлей существует только у
  мастера — игрокам он не отправляется и не рисуется.
* **Игроки** видят только результат маски, и только если включён чекбокс
  «Показать игрокам» (`scene.fog.enabled`). По умолчанию он выключен: мастер
  готовит туман, а игроки продолжают видеть карту. Любой мазок/«Открыть всё»/
  «Скрыть всё» включает флаг автоматически, снять его можно тем же чекбоксом.
* Маска применяется к активной карте; остальные карты сцены туманом не
  накрываются.

### Синхронизация

Маска — часть сцены и ходит тем же каналом, что сетка и слои: `commitFog`
(`static/table.js`) → `scene_update { fog }`. Сервер (`src/realtime.rs`) валидирует
её `scenes::normalize_fog`:

* `by_map` — объект; ключ — id карты до 64 символов (маски несуществующих карт
  отбрасываются через `restrict_fog_to_maps` по `scene_items.layer = 'map'`);
* до 200 фигур на карту, координаты — конечные числа в пределах ±10⁷;
* `mode` — только `reveal`/`hide`; `shape` — `rect`/`circle`/`polygon`/`path`
  (`poly` старого клиента принимается и становится `polygon`);
* у `path` обязательна `width` (0 < width ≤ 10000); у прямоугольника и круга
  ровно две точки, у многоугольника 3–256, у мазка 2–2048;
* битые фигуры/записи отбрасываются, остальное сохраняется в `scenes.fog` (JSON)
  и рассылается всем нормализованным. Если `by_map` нет (старый формат), сервер
  туман не меняет — миграцию делает клиент.

## Линейка

`TableModel.snapRuler(points, grid, ctrl)` — чистая функция: концы линии
притягиваются к сетке (квадраты — к узлам/углам клеток, гексы — к центрам
гексов), `ctrl === true` возвращает свободные координаты. Длина и подпись —
`rulerCells` / `rulerLabel` (те же «N фт (M кл.)», что и раньше).

* По умолчанию линейка привязана к сетке. **Ctrl** (Cmd на macOS) — свободный
  режим; нажатие/отпускание Ctrl во время протяжки пересчитывает уже нарисованную
  линию по запомненным «сырым» координатам указателя.
* Кнопка «#» (привязка к сетке) выключает привязку и для линейки: тогда Ctrl не
  нужен — линия и так свободная.
* Рисование не менялось: свободные фигуры остаются свободными.

## Участники

Отдельная страница `static/table.html` + `static/table-page.js`, адрес
`/table/<id кампании>` (маршрут в `src/main.rs`; ссылка «Участники» — в шапке
стола, «Войти на карту» — обратно на `/c/<id>`).

* Список = персонажи кампании (`/api/characters?campaign_id=…`) + токены сцены
  без персонажа (NPC/монстры). Поиск по имени и фильтр «Все / В игре (на сцене) /
  Скрытые / Не на сцене».
* **«На сцену»** создаёт токен на слое персонажей в центре активной карты
  (позиция привязана к сетке) и берёт `sheet.token_asset_id`/портрет персонажа.
  **«Убрать»** удаляет токен, персонаж остаётся.
* Для токена правятся HP (текущие/максимум), скрытность (мастер), владелец
  (мастер); «токен-аватар» выбирается из `/api/assets?kind=token` и сохраняется
  в токен, а для персонажа — в `sheet.token_asset_id`.
* Данные — существующие API (кампании, сцены, персонажи, ассеты) и те же
  сообщения WebSocket, что у стола (`item_upsert`/`item_delete`), новый сервер не
  понадобился. Права те же, что на столе: игрок меняет только свои токены и HP.

## Сервер

`scenes.layers` (JSON) и `scenes.active_map_id` — новые колонки (`src/db.rs`,
миграция `ALTER TABLE` для старых баз). `GET` сцены отдаёт `layers` и
`active_map_id` (у старых сцен — `null`, клиент берёт слои по умолчанию).
`PATCH /api/campaigns/:cid/scenes/:sid` и WebSocket `scene_update` принимают
`layers`/`active_map_id` (валидация — `scenes::normalize_layers`), дубликат
сцены копирует слои (активная карта сбрасывается, т.к. элементы получают новые
id).

Туман хранится в существующей колонке `scenes.fog` (JSON), формат —
`{ enabled, by_map }`. `scene_update { fog }` валидируется `scenes::normalize_fog`
и `scenes::restrict_fog_to_maps` (см. «Туман войны → Синхронизация»), остальные
мастера и игроки получают уже нормализованную маску. `default_fog()` для новых
сцен — `{ "enabled": false, "by_map": {} }`; дубликат сцены получает чистую маску
(у копии новые id элементов, старые ключи `by_map` к ней не относятся). Старый
глобальный `shapes` сервер не читает и не пишет — миграцию делает клиент при
загрузке сцены.

## Ограничения

* Туман — маска на карту, но **активная карта одна на сцену** (у всех участников
  одна и та же). Маски неактивных карт хранятся, но не рисуются, пока карта не
  станет активной.
* Стек отмены тумана (до 20 шагов на карту) живёт в памяти клиента: перезагрузка
  страницы или приход другого мастера его очищает. Он не синхронизируется.
* Обрезка мазка (`path`) — визуальная и при проверке «открыто ли»: точки мазка
  не пересчитываются по границе карты (у `rect`/`circle`/`polygon` геометрия
  обрезается при добавлении).
* Маска считается на клиенте: сервер проверяет формат и лимиты, но не
  пересчитывает геометрию. «Открыто ли» на сервере никто не спрашивает —
  видимость токенов по-прежнему задаётся их флагом `hidden`.
* Одновременное редактирование тумана двумя мастерами не сливается: побеждает
  последний валидный `scene_update` (как и у сетки/слоёв).
