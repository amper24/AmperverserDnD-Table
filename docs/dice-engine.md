# Единый модуль бросков

`static/dice.js` загружается после `common.js` в лобби/столе и листе персонажа.
Он не требует CDN, WebGL, Three.js или сторонних библиотек. Старый `rollDice`
сохранён как совместимый алиас чистого `DiceEngine.evaluate`.

## API

```js
// Основной вход для пользовательского действия: локально или на сервер стола.
// `audience` — кому показать: 'all' (по умолчанию), 'gm' (только мастера), 'self' (только себе).
DiceEngine.submit({ type: 'roll', expr: '2d20kh1+5', label: 'Атака', kind: 'attack', audience: 'gm' });
DiceEngine.submit({ type: 'multi', label: 'Меч', rolls: [
  { name: 'Атака', kind: 'attack', expr: 'd20+5' },
  { name: 'Урон', kind: 'damage', expr: 'd8+3' }
] });

// Чистый локальный расчёт (без анимации/сети).
const result = DiceEngine.evaluate('4d6kh3');
DiceEngine.present(result, { local: true });

// Вход только для новых событий WebSocket, НЕ для истории чата.
DiceEngine.receive(chatMessage);
```

`Modules.roll` и `rollMulti` остаются адаптерами: подставляют переменные листа,
применяют режим и вызывают `submit`. Чат, панель стола, инициатива токена,
характеристики/навыки/спасброски/атаки листа, действия предметов/заклинаний,
формулы в заметках и мастер создания используют общий движок/рендерер.

## Результат

```json
{
  "expr": "4d6kh3+2", "total": 15,
  "parts": [
    { "term": "4d6kh3", "sides": 6, "rolls": [2, 2, 5, 6],
      "kept": [2, 5, 6], "kept_indices": [0, 2, 3] },
    { "term": "+2", "value": 2 }
  ]
}
```

Сохраняются **индексы** оставленных кубиков, поэтому одинаковые значения не
приводят к ошибке отображения. Для старых записей без индексов учитывается
кратность значений `kept`. При равенстве сохраняется более ранний кубик.

Грамматика: сумма/разность целых чисел и `NdS`, `NdSkhK`, `NdSklK`, кириллическая
`к` допускается. До 64 символов, 32 слагаемых, суммарно 100 кубиков, 1–1000 граней,
модификаторы до 1 000 000; `1 <= K <= N`. Дроби, нераспознанные фрагменты,
повторные знаки и частичные формулы отклоняются, а не молча игнорируются.
Локальный RNG — `crypto.getRandomValues` с rejection sampling, серверный — Rust
`rand::thread_rng`. `Math.random` используется только для движения моделей.

## Сеть и приватность

- На столе результат генерирует **только сервер**. Визуализация получает готовые
  `parts` и `total`. Загрузка истории не запускает старые анимации.
- Каждый запрос получает `request_id`; сервер возвращает его в результате или
  персональном `roll_error`. Ошибка внутри связки отменяет всю связку.
- При обрыве соединения нет локального «запасного» броска или автоматического
  повтора: пользователь получает ошибку/таймаут и может проверить чат.
- Аудитория броска — `all` / `gm` / `self` — задаётся в сообщении (`audience`) или
  общим селектором «Кому:» в доке и журнале; выбор запоминается в `dice-settings`
  и применяется ко **всем** кнопкам броска: лист, справочник, чат, панель стола.
  Сервер по-прежнему понимает поля `gm_only` и `visibility`.
- Скрытые броски доступны GM. Попытка игрока не превращается в публичный бросок,
  а выдаёт ошибку и не отправляется.
- Встроенный лист передаёт запрос same-origin столу; анимация одна — поверх стола.
  Отдельное окно с живым opener-столом дополнительно получает результат в своём окне.
  Внешний iframe-хост превью не используется как транспорт.
- Без открытого стола лист бросает локально, с явной подписью «Локальный бросок».
- Создание характеристик и сбор инициативы со стола — локальные операции, как и
  ранее. Они теперь используют тот же расчёт и визуализацию. Итог инициативы
  публикуется существующим механизмом трекера.

## Связки, преимущество и крит

Alt — преимущество, Ctrl/Meta — помеха, одновременно оба — обычный бросок.
Shift — скрытый бросок GM. Если формула содержит d20, режим меняет первый d20;
иначе — каждый пул костей формулы. Поэтому режим работает с любыми гранями и
действиями, включая урон и лечение, а бонусы сохраняются. Для отрицательного
слагаемого направление выбора инвертируется, чтобы преимущество увеличивало,
а помеха уменьшала итог. Обычный пул `NdS` превращается в `2NdSkhN`
(или `2NdSklN`); у формулы с явным `khK`/`klK` удваивается пул кандидатов и
сохраняется `K`. Уже готовый
`2dSkh1`/`2dSkl1` переключается между режимами без повторного удвоения.
Некорректная исходная формула не исправляется режимом — она отклоняется.

Естественная 20 атаки в связке удваивает **кости** последующего урона, не
модификатор и не лечение. Следующая атака задаёт новое состояние крита.
Натуральная 20 проверки/спасброска отмечается, но не считается автоуспехом или
критическим уроном. `base_expr` сохраняет исходную формулу: повтор связки не
удваивает уже удвоенные кости ещё раз. Чтобы связка не теряла урон при крите,
клиент также проверяет лимиты потенциально удвоенной формулы до отправки.

## Визуализация и настройки

Canvas 2D рисует вращающиеся проекции объёмных многогранников, тени, гравитацию,
отскоки, трение. Это облегчённая косметическая симуляция,
**не физический генератор случайных чисел** и не движок Foundry Dice So Nice.
D4/D6/D8/D12/D20 имеют соответствующие меши; D10/D100 и нестандартные кости
используют стилизованную модель.

**Пол — это поверхность экрана.** Кости вылетают из-за угла кадра и из-за дальнего
края «пола», летят по перспективе (горизонт на 16 % высоты, масштаб по глубине
0,44…1,0), падают с отскоками, катятся и гасят вращение трением. Остановившись,
кость доворачивается к зрителю гранью с результатом и аккуратно занимает свою
дорожку, поэтому итоговая раскладка читается даже при десятке костей. Последний
кадр принудительно фиксирует каждую модель на точной ориентации выпавшей грани:
скорость кадров и случайное вращение не могут оставить на кубике другое число.

**Числа нарисованы на гранях.** Каждая кость несёт свои значения, а когда кубик
останавливается, он доворачивается к зрителю той гранью, которая выпала:
передняя грань подсвечена белым, боковые — полупрозрачные. У «процентных»
костей (d100) граней меньше, чем значений — число показывается на ближайшей.
Значение берётся из результата броска, а не из положения модели.

Цифры крупные: размер считается от радиуса кости и среднего размера грани —
одна цифра почти заполняет грань, две и три ужимаются. До 24 моделей в одной
анимации; расчёт и журнал содержат все кубики. Журнал — 50 результатов в памяти
вкладки.

## Интерфейс: док слева, журнал справа, бросок — на весь экран

Кубики — не отдельная кнопка и не модальное окно:

- **слева внизу** — постоянный док броска: быстрые кости к4…к100 (Shift — дважды),
  режим «Обычно / Преим. / Помеха», модификатор, своя формула с Enter и
  «скрытый» бросок у мастера. Док сворачивается в одну кнопку (`dicetray_min`);
- **справа внизу** — личный журнал этой вкладки: последние 50 бросков, повтор,
  настройки анимации и быстрый бросок. Открывается в любой момент,
  счётчик показывает число бросков;
- **результат** — крупная полноэкранная сцена поверх стола/листа, а не маленькое
  окно визуализации. Кубики летят и останавливаются на общей поверхности экрана;
  автор, название действия, аудитория броска и большие итоговые числа видны
  поверх анимации.
  Новый бросок добавляется отдельной сценой и не заменяет уже летящие/лежащие
  кости: одновременно остаются до десяти последних сцен, одиннадцатая убирает
  самую старую. Сцена сама уходит через несколько секунд, Escape убирает все
  результаты. Полноэкранный слой прозрачный для мыши — стол и лист остаются
  доступны во время броска; подробный журнал по-прежнему открывается отдельно.

Публичные броски кампании отображаются на экране у всех участников, которым
разрешено видеть результат; личные и мастерские остаются приватными. При
выключенной анимации или `prefers-reduced-motion` крупный итог всё равно
появляется на общем экране без канваса. Док ставится `DiceEngine.dock({ gm })`
на столе и `DiceEngine.dock()` на листе; обе страницы используют один журнал и
один канал бросков.

`dice-settings` и `dicetray_min` хранятся через существующий consent-aware `LS`
и удаляются при отзыве согласия на функциональное хранилище. История бросков
не пишется в localStorage.

## Тесты

```sh
node --test tests/*.test.cjs
cargo test dice_tests
```

Опциональная браузерная проверка (Playwright + установленный Chromium):

```sh
node tests/dice.browser.cjs
```

Она проверяет полноэкранные параллельные сцены, крупный размер канваса и
отрисовку пикселей анимации, прозрачность слоя для кликов, reduced motion,
результат сервера без локального переброса, дедупликацию, аудиторию бросков,
запрет скрытого броска игрока, обрыв соединения, крит/повтор и мобильный экран.
В ограниченной среде допускается `SPARTICUZ=1` с пакетом `@sparticuz/chromium`.

Грани и доворот результата проверяются отдельным прогоном на мок-канвасе:
из последнего кадра анимации берутся все нарисованные числа и проверяется, что
у каждой кости ровно одна передняя грань и её число равно результату броска.
